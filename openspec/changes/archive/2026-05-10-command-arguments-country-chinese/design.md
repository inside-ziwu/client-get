## Context

当前采集与清洗主干已经大量使用 `country_iso3` 作为国家标准键，例如腾道 raw、外贸通 raw 与 clean company 去重路径。用户本次新增的是 admin/tenant 客户数据国家展示/筛选规则：admin 客户数据/干净公司库，以及 tenant 客户公司/精选客户中，面向人的国家名称必须显示中文，筛选交互也使用中文国家名，但后端查询、去重、供应商调用仍使用 `country_iso3` 或供应商要求的机器参数。

这条规则与现有 `country_iso3` 不冲突：ISO3 继续作为系统内部稳定键。筛选时用户可以选择“中国”这类中文值，但前端提交或后端执行逻辑必须转换或保留为 `CHN` 这类 ISO3 键；同理，“美国”对应 `USA`。admin 客户数据/干净公司库继续保存 `country_iso3`，tenant 客户公司/精选客户继续消费后端返回的机器键，前端可展示中文且中文筛选能映射命中 ISO3 数据，因此不需要正式数据 update。

## Goals / Non-Goals

**Goals:**

- 在 admin 与 tenant 客户数据列表、详情、精选客户和筛选中新增国家中文化规则。
- 第一版提供小型 ISO3 到中文名称映射，使 `USA`、`CHN`、`DEU` 等已支持 ISO3 能确定性展示为中文国家名称。
- 中文输入原样展示；未知值原样保留，避免猜测式转换。
- 明确 admin 客户数据/干净公司库不做国家字段数据 update，中文化通过展示/筛选映射完成。

**Non-Goals:**

- 不改变现有 `country_iso3` 作为内部国家标准键的设计。
- 不新增数据库 schema、外部依赖或新的采集供应商接口。
- 不在实施阶段自动连接或批量修改生产数据库。
- 不要求一次性覆盖全球国家、ISO2、英文名或别名；第一版只覆盖当前前端筛选和展示需要的 ISO3 样本，并保留小表扩展点。

## Decisions

### D1. 内部键与展示/参数值分层

系统内部继续使用 `country_iso3` 参与去重、筛选、供应商调用与关联；admin/tenant 客户数据中面向人展示和筛选交互的国家值统一为中文国家名称。

原因：现有清洗主干、索引与唯一约束已经围绕 ISO3 建立。直接把内部键改为中文会扩大改动面并引入回归风险；在 admin/tenant 展示/筛选层做中文化可以满足运营一致性，同时保持底层稳定。

### D2. 新增小型 ISO3 到中文展示能力

实现层应提供“ISO3 → 中文名称”的小型前端展示能力。第一版映射以 `USA -> 美国`、`CHN -> 中国`、`DEU -> 德国` 为基础，并按 admin/tenant 当前筛选 options 和测试样本补齐。中文输入原样返回；未知 ISO3 或未知字符串原样返回。admin 与 tenant 展示/筛选中文化不得使用 fuzzy first-match。

原因：当前后端和数据库已经使用 ISO3 作为机器键，前端只需要把已知机器键渲染成人类可读中文，并把筛选 option 的 value 保持为 ISO3。引入完整国家解析会扩大范围，也更容易产生误判。

### D3. 歧义值不猜测

当输入值无法通过小型映射表映射到明确中文国家时，展示逻辑不得猜测为某个中文国家；应原样展示该值。

原因：国家字段会影响 admin/tenant 展示和筛选，错误转换比未转换更难排查。原样展示能保留可追溯性。

### D4. 干净公司库不做数据 update

admin 客户数据/干净公司库的国家存储值保持 `country_iso3`，不为了中文展示而 update 为中文。中文展示与中文筛选通过映射层完成：展示层把 `USA` 渲染为 `美国`，筛选层把用户选择的 `美国` 转换为 `USA` 后查询。

原因：`country_iso3` 是去重、筛选、供应商调用和关联的机器键。强行 update 干净公司库国家字段会破坏机器键语义，也没有必要。

### D5. 国家映射放在前端共享模块，不上后端或数据表

国家中文展示/筛选映射放在前端 workspace 共享模块中，优先落在现有 `@shared/types` 包，例如新增 `frontend/packages/shared-types/src/countries.ts` 并从 `src/index.ts` 导出。该模块提供小型常量表和纯函数，例如 `COUNTRY_NAME_ZH_BY_ISO3`、`displayCountryName()`、`countryOptionsZh()`；admin 与 tenant 共同复用。

原因：当前前端已有 pnpm workspace，admin 与 tenant 都依赖 `@shared/types`。国家映射是无 React、无 antd、无网络请求的领域常量/展示 helper；放 `@shared/types` 可避免新增包、避免 app 内重复表。当前需求只要求中文中后台展示/筛选，不需要后端承担 UI 文案职责。

## Risks / Trade-offs

- [映射覆盖不足] 部分少见 ISO3 无法中文化 → 第一版原样展示，后续按实际筛选/展示需求补充小表。
- [中文名称口径不一致] “美国/美利坚合众国”等长短名称混用 → 第一版统一使用常见中文简称，后续如需官方全称再单独变更。
- [与 ISO3 展示混淆] admin 客户数据列表或详情仍展示 ISO3 → 本 change 要求 admin 客户数据列表、详情和筛选控件完成中文化。
- [误改数据风险] 为了展示中文而 update 干净公司库会破坏 `country_iso3` 机器键 → 本 change 明确不 update 干净公司库国家字段，只做展示/筛选映射。
- [共享包语义偏差] `@shared/types` 名称偏类型，但本次会承载少量运行时常量 → 第一版接受该轻微不纯，优先换取最小接入成本。
