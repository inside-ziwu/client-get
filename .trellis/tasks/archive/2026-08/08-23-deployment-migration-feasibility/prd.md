# 部署迁移可行性评估

## Goal

评估将 ClientGet 从 Sealos 迁移到更低成本部署环境的可行性，在不削弱租户数据隔离和邮件发送可靠性的前提下，形成有数据依据的目标架构、月成本估算、迁移风险与决策建议。

## Background

- 当前系统部署在 Sealos，用户报告月费用约为 `512+`，认为成本偏高；币种、账单构成与统计周期尚待账单证据确认。
- 用户提出的初步方向是：
  - 对象存储（OSS）保存不常用的原始采集数据；
  - 数据库仅保存清洗后、需要在线查询的数据；
  - 普通服务器承载程序代码与后台任务。
- 项目是多租户获客与邮件营销 SaaS，任何迁移不得削弱租户隔离、发送幂等、收件人时区/工作日窗口以及发信域名信誉保护。

## Confirmed Facts

- 生产存在 Instance A / B，两实例运行同一套代码、共享同一个物理 PostgreSQL 数据库，并通过 `instance_id` 做逻辑隔离；API、发送 worker、Admin 前端和 Tenant 前端是不同运行角色。
- 2026-08-23 对生产库执行的只读元数据体检确认：
  - 数据库总容量为 `36,588,003,811` 字节（约 36.6 GB / 34.1 GiB）。
  - `waimaotong_keyword_raw_contacts` 约 1,786 万行、24.43 GB；`waimaotong_keyword_raw_companies` 约 38.9 万行、3.24 GB。
  - 上述两张关键词采集原始表合计约 27.67 GB，占全库约 75.6%；全部原始层合计约 30.57 GB，占约 83.6%。
  - 若能安全移走全部冷原始层，保留数据库体量的理论下限约为 6 GB；实际还需为热原始索引、迁移双写空间、增长余量和备份留量。
- 最大的两张关键词原始表由外部采集 / 清洗程序直写，本仓库业务代码零读取，但清洗结果会进入在线 `waimaotong_clean_*` 表；这些表的 schema 主权不在本仓库，不能单方面迁移或删除。
- 并非所有名为 raw 的表都可直接离线：`waimaotong_raw_companies` 仍参与租户列表、采集类型判定和评分证据；部分原始表还由 Admin 只读页面访问。
- 按 Sealos 北京区公开单价估算，30 GB 存储卷本身约 11.3 元 / 月；阿里云 OSS 标准本地冗余示例价为 0.12 元 / GB / 月，30 GB 约 3.6 元 / 月（均未计请求、取回和流量）。因此，仅替换存储介质不足以解释或消除约 512 的月费，主要节省应来自数据库缩容和应用计算资源整合。

## Requirements

- 盘点当前部署拓扑、应用进程、数据库、后台任务、持久化文件及外部依赖。
- 识别原始采集数据、清洗中间数据和在线业务数据的生命周期、访问模式与关联关系，判断哪些数据适合转入对象存储。
- 建立当前成本基线，并对至少两个可落地的目标部署方案进行同口径月成本比较。
- 评估对象存储分层对查询、重跑清洗、去重、审计、备份恢复及租户隔离的影响。
- 给出目标架构边界：服务器、数据库、对象存储分别承载什么，不承载什么。
- 给出迁移步骤、验证点、回滚条件、停机影响及主要运维风险。
- 给出明确结论：可行 / 有条件可行 / 不建议，并说明预计节省、前置条件与触发扩容的阈值。

## Acceptance Criteria

- [ ] 现状成本按计算、数据库、存储、网络流量、备份及其他托管能力拆分，所有未知项明确标注而非猜测。
- [ ] 数据按热、温、冷分层，并逐类说明保存介质、保留期限、读取路径和恢复方式。
- [ ] 至少两个候选方案使用相同容量与流量假设估算月成本，并列出一次性迁移成本。
- [ ] 推荐方案覆盖租户隔离、邮件可靠性、备份、监控、故障恢复与安全边界。
- [ ] 结论包含可验证的试迁移方案和 Go / No-Go 判据。
- [ ] 评估报告足以支持用户决定是否迁移，但不会在未获单独授权时改动生产环境或发起外部写操作。

## Out of Scope

- 本任务不执行生产数据库写入、正式迁移、切流、部署或外部平台配置变更。
- 不重新设计业务功能，也不引入项目已明确排除的回信监控能力。

## Open Questions

- 当前 `512+` 的币种、完整自然月账单构成，以及各应用 / 数据库的 CPU、内存、存储卷、端口和流量规格。
- 目标部署地域、备案 / 中国大陆访问约束。
- 可接受的 RPO / RTO，以及是否接受自行运维 PostgreSQL 与单机故障域。
- 外部采集 / 清洗程序是否在本次迁移范围内，能否配合改为 OSS + 热索引 / 清单表的数据契约。
