# Codex 独立评审（第二视角，2026-08-23）

> 经 `trellis channel run --provider codex` 产出；输入为 prd / design / implement（v1）与三份核证结果。

## 总体结论

三份核证把「按字面写会翻车」的实现坑基本扫清了；**现在真正会出事的是产品口径、共库运维和施工文档没跟上核证**。按附件里的 `implement.md` 直接开工，会把已经证伪的步骤再做一遍。功能能做，但有几处会让 AC3/AC4/首日体验对不上。

## 三份核证之外的新问题（编号；问题 → 依据 → 建议）

1. **`implement.md` 仍是核证前文本，施工会走错路**  
   附件 A1 还在同步 `schema.sql`、B1 还写「生产 0 行」、B2 还要改并不存在的 `maintain_partitions.py` 条目、A7 还是事务锁。核证已证明这些会空耗或无互斥。  
   **建议：** 编码前先把核证结论回写 design/implement，否则 PR A 第一步就偏。

2. **首轮抓取会把站点历史灌进「未读行业动态」**  
   窗口按 `fetched_at`，RSS 常带回几十条旧稿；它们全部算未读、全部落在 90 天窗口里，只是按 `published_at` 沉底。AC3「当天新增出现在顶部」对这批旧稿不成立；用户第一天是多页旧闻。核证只当索引问题提过，没当验收风险。  
   **建议：** 展示再加一条：`published_at` 有值则也须落在 90 天内；或首轮只插入 90 天内条目。改 PRD 一句，别让 QA 按 AC3 字面打回。

3. **停用源与空态口径打架**  
   `list_items` 未滤 `is_active`，`filters` 只看启用源。全停用 → 租户看到「尚未配置动态源」，API 仍可能有历史条目；单源停用后条目还在，筛选里却没这个来源。R1 说的是「没有启用动态源」。  
   **建议：** 列表也滤启用源（或明确「停用=停抓、旧稿仍可见」并让 `has_sources` 看「是否曾配置」）。二选一写进 design。

4. **种子按 `(instance_id, url)` upsert，AC4「改错地址」做不到**  
   改 URL 会插入新源、旧源仍在；管理端只读，页面不能改地址。运营修站点改版只能 SQL 或接受双行。  
   **建议：** upsert 键改成稳定 `code`/`name`；AC4 用「把 `parse_config` 改废」或 SQL `UPDATE url` 做，不要写「改种子 URL」。

5. **启动补跑只补「完全没跑」，不补「跑失败」**  
   失败也写 `last_fetched_at=now()`。早上 08:00 失败、下午发版重启，**不会**重抓，只能等次日或点「立即抓取」。  
   **建议：** 删补跑，只留 08:00 + 按钮（更简单）；或补跑条件改成 `max(last_success_at) < 今日 08:00`。

6. **「立即抓取」会撒谎**  
   锁被占返回 skip，接口仍 202，toast「已触发」，3 秒后 invalidate 也看不到健康变化。14 源×20s 超时，跑完可能要几分钟；API 进程里还夹着 `feedparser`/`selectolax` 同步解析。  
   **建议：** 进行中返回 `triggered: false, reason: in_progress`；文案改「已排队，请稍后刷新」；解析放到 `asyncio.to_thread`，避免卡事件循环。

7. **真站可达 ≠ Sealos 出口可达**  
   调研在开发侧 HTTP 可取；生产 API 从国内云出网，IPC / I-Connect007 / 慕尼黑两站可能 403 或空列表。A8「14 行每行 ≥1」会把站点偶发当成开发失败。  
   **建议：** 合并门禁用 fixture；上线后在 **A 实例容器内** dry-run 一次，允许当日某源 0 条，靠错误计数跟。

8. **B 实例管理端与误种子**  
   AC5 只说租户空态。B 的「动态源管理」仍有「立即抓取」，空列表无说明，像故障。`seed --instance` 不拦 `instance_b`，共库上误导入就破坏「B 不配源」。  
   **建议：** B 管理端空态写明未配置；seed 对非 `default` 要二次确认或拒绝。

9. **同稿去重 vs 来源筛选（AC2∩AC3）**  
   先抓到的源留下，姊妹站 30–50% 转载。按「落选源」筛选会看不到这篇，来源计数也不再是 14 源并集。  
   **建议：** 验收写清「按保留源筛选」；不要按 14 源条数对账。

10. **「只看未读」点标题后该行消失**  
    开关若随「查询」生效，点开原文再刷新会少一行，不像开关。PRD 没写。  
    **建议：** 接受「下次查询后移除」，测试别断言行还在。不要为即时生效改 FilterBar。

## 简化建议

- **删启动补跑**，发版靠按钮；少一整类时钟/重启风暴。
- **锁用单连接 + savepoint（核证方案 C）**，不要新做会话锁；每天十几源，整轮失败可重跑。
- **管理端 14 行不要 `paginated_response`**，`success_response` 足够。
- **不要上 tenacity**（全仓无用法）；手写 2 次重试即可。
- **两个 UNIQUE 都留**，插入只 `ON CONFLICT DO NOTHING`，删预 SELECT。
- **`/filters` 保留**（空态 `has_sources` 需要）；不要为乐观更新改 React Query 缓存，用 `clickedIds`。
- **不要改 FilterBar/TableState 契约**。

## 不同意的决定

- **不同意上会话级 advisory lock。** 仓库无先例，漏 unlock 会把每日抓取卡死；本功能不值得。
- **不同意把 R3「RSS 自动发现」悄悄删掉。** 可以不做，但必须在 design 写「有意偏离：无运营加源入口」。
- **不同意 A8 真站 14/14 作为合并门槛。** 那是环境问题，不是代码正确性。
- **不同意 AC3 与 R1 时间键混用。** 排序键是 `published_at ?? fetched_at`，「抓到的当天置顶」不是真的；改 AC3 或改排序，不能两个都验。
- **同意核证：不动 `schema.sql`、生产 `intelligence_sources` 先留档 2 行、B 迁移后不能回退旧镜像。**
