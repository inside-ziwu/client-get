# 按收件人当地时间智能发送

**日期：** 2026-05-29
**范围：** Admin 配置体系 + Tenant 发送逻辑 + 当地时间显示

## 概述

新增国家工作时间配置和时区感知发送能力。Admin 端维护配置体系（工作规则集、国家时区与假日、全局默认规则），Worker 发送时按收件人所在国家的当地时间判断是否在允许时段内，Tenant 端发送日志新增当地时间显示。

---

## 关键决策

- **规则集按工作模式分组，不按时区分组。** 同一规则集内的国家共享相同的工作日和时段定义（如「周一至周五 9:00-17:00」），但各国时区不同。工作时段表示当地时间，系统根据各国时区分别换算。这样美国和英国可以共用一个规则集，大幅减少配置量。
- **每国一个主时区。** 不按城市/地区细分到子时区。在 B2B 场景下，国家级精度的偏差可接受。
- **公共假日放在国家级别，不放在规则集内。** 同一规则集内不同国家的假日不同，假日天然是国家固有属性。
- **未配置国家使用全局默认规则。** 默认规则在 admin 端可配置，格式与规则集一致。收件人所在国家未关联任何规则集时，回退到默认规则。
- **复用域名级 daily_limit。** 每日发送上限沿用 `domain_warmup_status.daily_limit`，不新增限制维度。
- **当地时间为前端实时转换。** 后端只存 UTC 时间，前端根据收件人国家的当前时区配置实时换算显示。Admin 修改某国时区后，历史发送记录的当地时间会跟着变。
- **使用 IANA 时区标识，而非固定 UTC 偏移。** 系统必须使用 IANA 时区标识（如 `America/New_York`），由时区库自动处理夏令时 (DST) 切换。禁止使用固定 UTC 偏移量（如 `UTC-5`），否则每年夏令时切换时发送时间会偏移1小时。
- **跨天时段规则。** 工作时段中「开始时间 > 结束时间」（如 22:00-06:00）表示跨天，即从当天 22:00 到次日 06:00。工作日判定按「开始时间」所在日期：22:00 周五开始到 06:00 周六，只要周五是工作日即可发送。同一规则集内多个时段不允许重叠。

## 需求

### 国家与时区

R1. 系统内置全球国家列表（基于 ISO 3166-1 最新标准），包含国家名称、ISO3 代码、预置主时区（IANA 时区标识，如 `America/New_York`、`Asia/Shanghai`）。时区必须使用 IANA 标识，不使用固定 UTC 偏移，以正确处理夏令时。

R2. Admin 可查看国家列表，支持按名称/代码搜索，显示每个国家的名称、ISO3 代码、当前主时区、关联的规则集名称。

R3. Admin 可修改任意国家的主时区，从 IANA 时区列表中选择。

### 工作规则集

R4. Admin 可创建工作规则集，包含以下字段：
- 名称（必填，用于辨识，如「欧美标准」「中东模式」）
- 工作日（多选星期几，周一至周日）
- 工作时段（一个或多个时段，每个时段为开始时间-结束时间，表示当地时间）。支持多时段（如 09:00-12:00 + 14:00-18:00）和跨天时段（如 22:00-06:00，表示当天 22:00 到次日 06:00）。同一规则集内多个时段不允许重叠。

R5. Admin 可编辑已有规则集的名称、工作日、工作时段。

R6. Admin 可删除规则集。删除时，已关联的国家自动解除关联（回退到默认规则）。

R7. 在规则集详情页中，Admin 可添加或移除关联的国家。一个国家同一时间只能属于一个规则集；将某国添加到新规则集时，自动从原规则集中移除。

R8. 规则集列表页显示每个规则集的名称、工作日、工作时段、关联国家数量。

### 公共假日

R9. 系统为每个国家自动预填当年公共假日数据（AI 搜集），包含日期和假日名称。AI 搜集支持两种触发方式：国家 Tab 级别批量触发（选中多国一次搜集）和国家详情页内单国触发。

R10. Admin 可在国家详情页内手动修改、添加、删除假日条目。

R11. 假日列表按日期排序显示，支持按年份筛选。

### 默认规则

R12. Admin 可配置一套全局默认规则，字段与规则集一致：工作日（星期几）+ 工作时段（支持多时段和跨天）。

R13. 默认规则在系统初始化时预设为周一至周五 09:00 - 17:00，Admin 可随时修改。

R14. 默认规则的配置入口在国家工作时间配置页面内，与规则集列表同级展示。

### Admin 导航与页面结构

R15. Admin 侧边栏新增一级菜单项「发送时间配置」，点击进入国家工作时间配置页面。页面内部使用 Tab 切换组织三个功能区域：
- Tab 1「规则集」：规则集列表（创建/编辑/删除），点击规则集名称进入规则集详情页（新页面，非弹窗），详情页内管理关联国家。
- Tab 2「国家」：国家列表（搜索/筛选），点击国家名称进入国家详情页（新页面），详情页内修改时区和管理假日。
- Tab 3「默认规则」：内联表单直接编辑默认工作日和时段，无需跳转新页面。

### Worker 发送逻辑

R16. Worker 每轮处理时，逐封检查域名级每日发送额度（`domain_warmup_status.daily_limit`）。当日已达上限时，停止本轮发送。

R17. 对每个待发送收件人，根据其关联公司的 `country_iso3` 查找对应国家的时区和工作规则。将当前 UTC 时间转换为该国当地时间后，判断是否同时满足：当天是工作日（星期几匹配）、当天不是该国公共假日、当前时间在某个工作时段内。跨天时段的工作日按开始时间所在日期判定。

R18. 不满足 R17 条件的收件人跳过，保持未发送状态。Worker 下次轮询时重新检查，符合条件时正常发送。

R19. 收件人所在公司未填 `country_iso3` 或该国未关联任何规则集时，使用全局默认规则（R12）判断。仅使用默认规则的工作日和时段，时区使用该国预置时区；公司无国家时固定使用 UTC 时区（非服务器本地时区，避免随 Docker 环境漂移）。

R20. Worker 跳过收件人时，记录跳过原因（如「当地非工作时间」「当地非工作日」「当地假日」）。跳过原因在发送计划详情页的收件人 tab 中展示，帮助用户理解为何某些收件人尚未发送。

### Tenant 端显示

R21. 发送计划详情页「发送日志」tab 新增「当地时间」列，显示该封邮件发送时刻按收件人国家时区转换后的本地时间（前端实时转换）。保留现有「发送时间」列（北京时间），两列并排显示。

R22. 当地时间的显示格式与现有时间列一致（`YYYY-MM-DD HH:mm`），末尾附加时区缩写（如 `2026-05-29 09:30 EST`）。

R23. 发送计划详情页「计划信息」tab 增加收件人时区/国家分布概览，展示收件人按国家或时区区域的分布比例（如「美洲 45%，欧洲 30%，亚洲 25%」），帮助用户预期发送节奏。

### 技术清理

R24. 清理 `sending_plans.send_strategy` 中未使用的 `timezone_aware`、`preferred_hours`、`daily_limit` 字段。这些字段从未被 Worker 使用，本次新增的 admin 级配置体系已完全取代其原始意图。

## 关键流程

F1. **配置一个新地区的工作时间**
- **步骤：** Admin 进入「发送时间配置」→ 规则集 tab → 发现已有规则集（如「欧美标准」周一至周五 9-17）适用 → 进入该规则集详情页 → 添加目标国家 → 完成。若无合适规则集，先创建新规则集再关联国家。
- **覆盖：** R4, R7, R8, R15

F2. **为某国配置假日**
- **步骤：** Admin 进入「发送时间配置」→ 国家 tab → 搜索目标国家 → 进入国家详情页 → 查看 AI 预填的假日列表 → 根据需要修改或添加假日 → 完成。
- **覆盖：** R2, R9, R10

F3. **调整某国时区**
- **步骤：** Admin 进入国家 tab → 找到目标国家 → 进入国家详情页 → 修改时区为正确的 IANA 时区 → 保存。
- **覆盖：** R2, R3

F4. **Worker 一轮发送流程**
- **步骤：** Worker 触发 → 领取到期待发邮件 → 逐封处理：检查域名日限（达到则停止本轮）→ 查收件人国家 → 换算当地时间 → 判断工作日+非假日+时段内 → 满足则发送，不满足则记录跳过原因并跳过 → 处理下一封。
- **覆盖：** R16, R17, R18, R19, R20

F5. **Tenant 查看发送日志当地时间**
- **步骤：** 租户进入发送计划详情 → 切换到「发送日志」tab → 看到每封邮件的「发送时间」（北京时间）和「当地时间」（收件人所在国家时间）两列。
- **覆盖：** R21, R22

## 验收示例

AE1. **同规则集不同时区。** 美国（`America/New_York`）和英国（`Europe/London`）都关联到「欧美标准」规则集（周一至周五 9:00-17:00）。北京时间周一 21:00 时，纽约当地时间 9:00（在工作时段内），伦敦当地时间 14:00（在工作时段内）。两国收件人均可发送，但使用各自时区换算。
**覆盖 R1, R4, R7。**

AE2. **未配置国家走默认规则。** 某小国未关联任何规则集。发送时系统使用该国预置时区 + 全局默认规则（周一至周五 9:00-17:00）判断是否可发送。
**覆盖 R12, R13。**

AE3. **假日当天不发送。** 美国国庆日（7月4日）已在美国假日列表中（AI 预填）。该日即使是工作日（周五），且当地时间在 9-17 范围内，仍判定为不可发送。
**覆盖 R9, R17。**

AE4. **国家从一个规则集转移到另一个。** Admin 将沙特从「欧美标准」改为「中东模式」（周日至周四 8:00-16:00）。操作后沙特立即按新规则判断发送时间。
**覆盖 R7。**

AE5. **删除规则集后国家回退。** Admin 删除「中东模式」规则集，原关联的沙特、阿联酋自动解除关联，后续发送按默认规则执行。
**覆盖 R6, R12。**

AE6. **Worker 跳过非工作时段收件人并记录原因。** 发送计划包含美国和日本收件人。北京时间周一 10:00（纽约 22:00，东京 11:00）。Worker 处理时：日本收件人在工作时段内，正常发送；美国收件人不在工作时段内，跳过并记录原因「当地非工作时间」。下次 Worker 轮询时（如北京时间 22:00，纽约 10:00），美国收件人符合条件，发送。
**覆盖 R16, R17, R18, R20。**

AE7. **公司未填国家的收件人。** 某收件人关联的公司 `country_iso3` 为空。Worker 发送时使用全局默认规则的工作日和时段，按服务器时间判断，不做时区转换。
**覆盖 R19。**

AE8. **发送日志显示双时间。** 一封发给美国收件人的邮件于北京时间 `2026-05-29 21:30` 发送。发送日志「发送时间」列显示 `2026-05-29 21:30`，「当地时间」列显示 `2026-05-29 09:30 EDT`。
**覆盖 R21, R22。**

AE9. **跨天时段判定。** 某国规则集工作时段为 22:00-06:00（夜班场景）。该国当地时间周五 23:30，周五是工作日，判定为在工作时段内，可发送。当地时间周六 02:00，虽在时段内但工作日按开始时间（周五 22:00）判定，周五是工作日，可发送。当地时间周六 07:00，不在工作时段内，跳过。
**覆盖 R4, R17。**

AE10. **多时段判定。** 某国规则集配置两个时段 09:00-12:00 和 14:00-18:00。该国当地时间 13:00（午休），判定为不在任何工作时段内，跳过。当地时间 15:00，在第二个时段内，可发送。
**覆盖 R4, R17。**

AE11. **修改时区后历史记录变化。** Admin 将某国时区从 `Asia/Shanghai` 改为 `Asia/Tokyo`。租户查看之前的发送日志时，「当地时间」列按新时区 `Asia/Tokyo` 实时换算显示（而非发送时的 `Asia/Shanghai`）。
**覆盖 R3, R21。**

AE12. **时区分布概览。** 某发送计划有 100 位收件人，其中 45 位美国、30 位英国、25 位日本。计划信息 tab 显示「美洲 45%，欧洲 30%，亚洲 25%」。
**覆盖 R23。**

## 范围边界

- 发送计划创建流程不变，不涉及本次需求
- 收件人 tab 不新增当地时间列，当地时间仅在发送日志 tab 显示
- 不支持按城市/地区精确到子时区
- 假日数据由 AI 预填 + admin 手动修改，不对接第三方假日日历服务实时同步
- 不支持按个人行为数据优化发送时间（属于12月目标）

## 依赖与假设

- 收件人的国家来源于关联公司的 `country_iso3` 字段（已有数据）。公司未填国家时，该收件人走默认规则。
- IANA 时区数据库作为时区标识的标准来源，系统需内置国家到默认时区的映射表。
- 国家列表基于 ISO 3166-1 最新标准预置。
- 国家列表和时区映射通过数据库 migration seed 初始化，确保部署即可用。
- 公共假日由 admin 在国家详情页手动触发 AI 搜集，搜集结果写入数据库后可编辑。首次部署时假日列表为空，需 admin 手动触发搜集。
