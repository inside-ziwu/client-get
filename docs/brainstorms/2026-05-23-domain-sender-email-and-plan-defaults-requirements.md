# 域名发件邮箱 + 新建计划默认值

## Summary

Admin 域名管理增加发件邮箱字段、编辑和删除操作；tenant 新建计划时，基本信息三个字段（发件人名称、发件邮箱、发送域名）基于租户数据和域名配置自动填入默认值。

---

## Problem Frame

当前 admin 添加域名时只能设置域名和暖机配置，无法维护发件邮箱地址。域名也不支持编辑和删除。tenant 端新建发送计划时，基本信息的三个核心字段（发件人名称、发件邮箱、发送域名）没有默认值，用户每次都需要手动填写，重复且容易出错。

---

## Actors

- A1. Admin 运营人员：管理 tenant 的域名配置，包括添加、编辑、删除域名及维护发件邮箱
- A2. Tenant 用户：创建发送计划，使用域名和发件邮箱配置

---

## Requirements

**Admin 域名管理**

- R1. 添加域名时支持填写发件邮箱地址（完整邮箱格式，如 sales@example.com），一个域名对应一个发件邮箱
- R2. 域名支持编辑，可修改发件邮箱地址和暖机配置（暖机规则、暖机档位），域名本身不可修改
- R3. 域名支持删除，删除前需确认；当域名被活跃发送计划（running/scheduled 状态）引用时，禁止删除并提示用户

**Tenant 新建计划默认值**

- R4. 发件人名称默认取当前 tenant 租户名称（tenants 表 name 字段），支持修改
- R5. 发送域名默认取已验证域名中 created_at 最早的一个，支持修改
- R6. 发件邮箱默认取当前选中域名对应的发件邮箱地址，支持修改；若域名未维护发件邮箱则留空由用户手动填写
- R7. 切换发送域名时，发件邮箱自动更新为新域名对应的发件邮箱地址

---

## Acceptance Examples

- AE1. **Covers R3.** Admin 尝试删除某域名，该域名被一个 running 状态的计划引用 → 系统拒绝删除并提示"该域名正在被活跃发送计划使用，无法删除"
- AE2. **Covers R5, R6.** Tenant 新建计划，该 tenant 有 3 个已验证域名，最早添加的是 A 域名且维护了发件邮箱 info@a.com → 发送域名默认选中 A，发件邮箱默认填入 info@a.com
- AE3. **Covers R6, R7.** 用户将发送域名从 A 切换到 B，B 域名未维护发件邮箱 → 发件邮箱清空，用户需手动填写

---

## Success Criteria

- Admin 可以在域名维度完成发件邮箱的维护，域名支持完整的增删改操作
- Tenant 新建计划时基本信息表单自动填入合理默认值，减少手动输入

---

## Scope Boundaries

- Tenant 端不增加域名管理功能，保持只在新建计划时选择域名
- 不改动向导的其他步骤（配置步骤、收件人、确认）
- 发件邮箱为完整邮箱地址，不做 @ 前缀自动拼接

---

## Key Decisions

- 发件邮箱存完整地址：直接存储完整邮箱地址而非前缀拼接，简化取值逻辑
- 一域名一邮箱：每个域名只维护一个发件邮箱地址
- 域名删除约束：有活跃计划引用时禁止删除，保护数据完整性
- 默认域名取最早验证域名：按 created_at 升序取第一个 verified 域名作为默认
