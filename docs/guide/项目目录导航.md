# ClientGet 项目目录导航

## 一句话先说清

这个目录当前**不是一个单一项目仓库**，而是一个“工作区”：

- `frontend/`：前端实际代码仓
- `backend/`：后端实际代码仓
- `blueprint/00~09`：后端蓝图与设计文档
- `docs/`：已归档的历史资料、会议记录、会话记录、导航说明
- `.playwright-mcp/`、`.superpowers/`、`.claude/`：AI/工具运行痕迹

## 代码目录

### `frontend/`

前端主仓，独立 Git 仓。

- `apps/admin/`：平台管理端前端
- `apps/tenant/`：租户端前端
- `packages/shared-api/`：前后端接口调用封装
- `packages/shared-types/`：共享类型定义
- `packages/shared-hooks/`：共享 React Hooks
- `packages/shared-ui/`：共享 UI 组件
- `deploy/`：前端部署相关配置
- `node_modules/`：前端依赖安装产物

### `backend/`

后端主仓，独立 Git 仓。

- `app/api/`：API 路由层，按 `admin / tenant / internal / webhooks` 分组
- `app/services/`：业务服务层
- `app/schemas/`：请求与响应数据结构
- `app/core/`：配置、日志、错误、请求上下文等基础设施
- `app/db/`：数据库连接、事务、RLS 相关逻辑
- `app/security/`：鉴权、安全依赖、密码/JWT
- `app/integrations/`：第三方或外部系统对接
- `app/workers/`：异步 worker 执行单元
- `app/utils/`：通用工具
- `alembic/`：数据库迁移
- `tests/`：后端测试
- `scripts/`：启动 worker、seed、迁移辅助脚本
- `docs/`：后端运行、部署、回滚等操作文档
- `.venv/`、`.pytest_cache/`：本地 Python 运行产物

## 文档目录

### `blueprint/`

这是“后端蓝图总包”，不是纯代码目录。

- `00_original_sources/`：原始系统文档，作为追溯来源
- `01_final_repaired_docs/`：修复后的最终文档，优先级高于原始文档
- `02_architecture/`：后端架构、安全、认证设计
- `03_database/`：数据库设计与 schema 草案
- `04_api/`：API 合同与路由说明
- `05_services/`：服务设计说明
- `06_frontend_alignment/`：前后端对齐文档
- `07_implementation_plan/`：开发计划、任务清单、验收计划
- `08_references/`：溯源与待确认问题
- `09_self_audit/`：蓝图自审报告
- `machine_readable/`：给 Agent/脚本读取的结构化 YAML
- `docs/`：本轮开发过程文档、计划、问题记录、最佳实践

### `docs/`

根目录文档整理区，专门收纳散落资料。

- `guide/`：工作区导航文档
- `meetings/`：会议记录
- `session-records/`：历史 AI 会话记录
- `source-materials/`：原始需求资料、业务背景文档、流程图
- `archive/system-docs/`：归档的重复旧文档

### `docs/archive/system-docs/`

这是一份**重复文档目录**。

- 它与 `blueprint/00_original_sources/` 内容一致
- 唯一差异是 `00_original_sources/` 里多了 `business-flows-v2.html`
- 现在已经从根目录移入 `docs/archive/`，避免与主文档混在一起

## 根目录保留文件

整理后，根目录只保留需要直接可见的主入口和配置：

- `opencode.json`：工具配置文件
- `docs/`：归档资料与导航
- `frontend/`：前端代码
- `backend/`：后端代码
- `blueprint/`：后端蓝图与设计依据

## 工具与运行痕迹

- `.playwright-mcp/`：浏览器自动化工具缓存/运行目录
- `.codex/`：Codex 技能与本地配置
- `.opencode/`：OpenCode 工具运行目录
- `.claude/`：Claude/Codex 类工具配置
- `.DS_Store`：macOS 目录元数据

这些通常不属于业务代码。

## 当前最容易让人看晕的点

1. 根目录同时放了“原始资料、蓝图文档、前端代码、后端代码、工具缓存”。
2. 前端和后端各自是独立 Git 仓，不是一个统一 monorepo。
3. `docs/archive/system-docs/` 与 `00_original_sources/` 仍然是重复关系，只是现在被归档了。
4. `docs/source-materials/business-flows-v2.html` 与蓝图包内同名文件重复，保留只是为了方便查原始资料。
5. `frontend/apps/admin/{src` 和 `frontend/apps/tenant/{src` 的空残留目录已经清理。

## 建议你以后这样理解这个工作区

按功能把它分成 4 块看：

1. `frontend/`
   前端实际代码
2. `backend/`
   后端实际代码
3. `blueprint/`
   后端设计蓝图和实现依据
4. `docs/` + `.playwright-mcp/` 等
   历史输入资料和工具痕迹
