## 0. 全局架构决策

> 以下决策贯穿整个系统，影响所有场景的实现方式。

### 0.1 评分体系：规则为主 + LLM辅助

- **主体**：规则化多维度打分（S/A/B/C/D 五级），取代现有系统的纯LLM AI评级（A/B/X）
- **LLM辅助场景**：语义匹配度打分（产品/行业匹配需要LLM判断相关性），扣租户AI余额
- **评分费用归属**：租户承担（扣租户AI余额）

### 0.2 公司数据归属：混合模式

- **原始采集数据**：共享去重（共享公司池 `shared_companies`）
- **租户视图**：完全隔离，各租户独立维护自己的公司状态/评分/标签/黑名单
- **租户数据可见范围**：仅本租户关键词关联的公司（严格隔离）
- **业务员数据隔离**：租户内共享，所有业务员看到相同数据（无业务员级别隔离）

### 0.3 计划生命周期：彻底拆分

- 采集/评分/发送各自独立实体和生命周期
- 现有 `email_plans` 的9状态流水线**不再保留**
- 发送计划只管"发送"，不负责采集和评分

### 0.4 流程调度架构：混合模式

- 保留中央调度器推进核心链路（采集→评分→邮件生成→发送）
- 采集服务独立部署，但通过**API调用**（非消息队列）与主系统通信
- **不引入消息队列基础设施**（务实选择，适配一人+AI团队规模）

> ⚠️ **矛盾修正 #3**：原需求文档后台任务A注释写"通过消息队列与主系统通信"，已确认为 API 调用。

### 0.5 AI模型路由

- 所有模型（Gemini 2.5 / GLM 5 / DeepSeek / 豆包）通过 **OpenRouter 统一路由**
- 平台级统一管理 API Key，租户无感

### 0.6 回复邮件处理

- **"回复可见型"**：系统接收并存储回复内容，可在系统内查看原文，继续沟通引导到外部邮箱
- **接收机制**：待调研（需先确认 EngageLab 是否支持 inbound 邮件解析）

### 0.7 通知机制

- Phase 1 仅站内消息，不引入短信/邮件/微信通知

### 0.8 租户行业属性

- 单行业（创建时选一个行业），不支持多行业

## 1. 角色与权限模型（RBAC）

### 1.1 角色体系：3角色

| 角色 | 标识 | 权限范围 |
|------|------|----------|
| **管理员** (Admin) | `admin` | 全功能：关键词配置、评分规则调整、联系人规则、模板管理、发送计划、群组管理、AI余额查看、团队账号管理 |
| **业务员** (Operator) | `operator` | 日常操作：浏览公司列表、优选客户、群组管理、模板使用/创建、发送计划创建/执行、邮件监控 |
| **只读观察者** (Viewer) | `viewer` | 仅查看：浏览公司列表、优选客户、邮件监控数据、情报中心，不可创建/修改/执行任何内容 |

### 1.2 角色创建

- 平台运营在创建租户时设置初始管理员账号
- 管理员可在租户后台创建业务员和只读观察者账号
- 平台运营也可直接为租户创建团队账号（任意角色）

### 1.3 数据隔离

- 所有角色仅可见本租户关键词关联的公司数据
- 租户内所有角色（管理员/业务员/观察者）看到相同数据范围

## 2. 数据模型核心约定

### 2.1 核心数据表结构（已确认）

| 表名 | 用途 | 说明 |
|------|------|------|
| `shared_companies` | 共享公司池 | 所有数据源采集的公司原始数据，用 `source_type` 机器枚举区分来源（`waimao_tong / tengdao / lixiaoyun`），界面展示渠道别名编码（A01/B01/C01） |
| `shared_contacts` | 共享联系人 | 与 `shared_companies` 关联的联系人信息 |
| `competitor_companies` | 竞对公司 | 励销云路径采集的中国同行公司信息 |
| `tenant_companies` | 租户公司视图 | 每个租户对公司的独立状态（评分/评级/标签/黑名单等） |
| `collection_keywords` | 采集关键词 | 记录租户配置的关键词；系统汇总后去重调度，实现多租户关键词重叠时的共享采集 |

### 2.2 去重唯一键

> ⚠️ **矛盾修正 #1**：原需求文档写"客户公司名称"为唯一键，已确认修正。

- **主键**：数据源ID（外贸通ID / 腾道ID / 励销云ID）
- **辅助**：公司名称（用于跨数据源的模糊去重）
- 同一公司在不同数据源有不同ID时，以公司名辅助判断是否为同一实体

### 2.3 多租户关键词重叠处理

- 关键词去重后统一采集，结果自动关联到所有配置了该关键词的租户
- 每个租户独立计费（即使数据源侧可去重/缓存，采集费用按租户独立计算）

### 2.4 余额耗尽时的行为

| 功能 | 余额为0时 |
|------|-----------|
| **评分（LLM辅助维度）** | 暂停该租户全部评分，新入库公司标记"待评分"，充值后统一补评 |
| **情报AI摘要** | 仅展示原文标题和链接，不做AI深度处理 |
| **邮件AI生成** | "AI生成"按钮置灰，提示"AI余额不足，请充值" |
| **AI数据分析** | "AI分析"按钮置灰，提示充值 |
| **邮件发送/浏览数据** | 不受影响，正常使用 |
| **纯规则评分维度** | 不受影响，正常评分（仅LLM辅助维度暂停） |

## 3. Phase 0 — 基础搭建

> 系统上线前，平台运营先完成以下配置。

### 场景①：配置数据源渠道与账号

- **操作者**：平台运营
- **频率**：一次性 + 按需调整
- **前置条件**：无，系统上线后第一件事

#### 步骤

**Step 1：添加采集渠道与别名**

在管理后台"数据源管理"中添加采集渠道，设置渠道别名（对租户脱敏）：

| 渠道 | 别名编码 | 用途 |
|------|----------|------|
| 外贸通 | A01 | 按关键词直接搜索海外采购商/公司 |
| 腾道 | B01 | 按关键词搜索海关进出口数据、采购商 |
| 励销云 | C01 | 搜索中国同行 → 反查其出口对象 → 获取精准客户 |

- 平台运营可自定义渠道别名，后续新增渠道时在此添加

**Step 2：配置渠道账号密码**

- 为每个渠道录入平台级账号密码，支持多账号轮换
- 外贸通/腾道/励销云：各录入账号密码，支持配置多个账号方便切换
- 账号密码集中在平台运营侧维护，方便在账号受限时快速切换

**Step 3：配置爬取频率**

- 请求间隔：如 30 秒/次（避免被数据源封IP）
- 每次批量上限：如单次最多抓取 100 条
- 每日执行时段：如凌晨 02:00-06:00

**Step 4：配置数据落库规则**

两条采集路径：

- **路径一（外贸通 + 腾道 → 直接采集）**：按租户关键词在外贸通和腾道搜索，搜到的海外公司信息直接落入 `shared_companies`
- **路径二（励销云 → 竞对反查）**：按租户关键词在励销云搜索中国同行公司，同行信息落入 `competitor_companies`；然后拿同行英文名去外贸通和腾道检索其出口对象，获得的精准客户列表落入 `shared_companies`，标记为"精准客户"

去重规则（⚠️ 已修正）：
- **唯一键 = 数据源ID为主，公司名辅助**（非原文档的"客户公司名称"）
- 统一表用 `source_type` 机器枚举区分来源（`waimao_tong / tengdao / lixiaoyun`），界面展示渠道别名编码（A01/B01/C01）

#### 关键约束

- 关键词由租户管理员在自己的后台配置（见场景⑧），不在此处
- 平台运营只负责维护渠道账号和爬取参数
- 系统汇总所有租户的关键词，统一调度采集任务

### 场景②：配置行业评分模板

- **操作者**：平台运营
- **频率**：一次性 + 按需调整
- **前置条件**：场景①完成（知道有哪些数据字段可用于评分）

#### 评分体系设计

评分分两层：
1. **平台运营提供行业默认模板**
2. **租户入驻时复制一份快照到自己空间**，之后可自由修改（快照机制）

#### 步骤

**Step 1：创建行业默认评分模板（平台侧）**

为每个行业创建 1 套默认评分模板。示例（PCB 行业，7 个维度）：

| 维度 | 规则示例 | 分值示例 | 评分方式 |
|------|----------|----------|----------|
| 工厂性质 | 贸易商/制造商/两者兼具 | 10/30/25 | 纯规则 |
| 公司规模 | 按员工数或注册资本区间 | 5-20 | 纯规则 |
| 进出口数据 | 有/无进口记录 | 0/15 | 纯规则 |
| 进出口频次 | 近12个月交易次数区间 | 0-20 | 纯规则 |
| 联系人丰富度 | 有效联系人数量区间 | 0-15 | 纯规则 |
| 数据来源 | 来源渠道编码 | 5-15 | 纯规则 |
| 产品/行业匹配度 | 产品关键词与租户行业的语义相关性 | 0-20 | **LLM辅助**（需调用AI判断） |

> **LLM辅助维度说明**：产品/行业匹配度等语义匹配类维度，需要调用LLM判断相关性，费用从租户AI余额扣除。租户余额为0时，该维度暂停评分，其他纯规则维度正常计算。

**Step 2：设定默认评级区间**

| 评级 | 条件 | 说明 |
|------|------|------|
| S级（精准） | 励销云反查路径获得 | 默认最高级别，不受常规评分规则限制 |
| A级（优质） | 总分 ≥ 80 | — |
| B级（良好） | 60 ≤ 总分 < 80 | — |
| C级（一般） | 40 ≤ 总分 < 60 | — |
| D级（低优先） | 总分 < 40 | — |

**Step 3：平台运营可随时调整**

- 可随时调整行业默认模板的维度、规则和分值
- **变更只影响之后新入驻的租户**
- 已入驻的租户持有入驻时刻的快照副本，不受回溯影响

### 场景③：维护行业情报源

- **操作者**：平台运营
- **频率**：一次性 + 按需调整
- **前置条件**：无，可与场景①②并行

#### 步骤

**Step 1：按行业创建情报源列表**

- 为每个行业维护一组情报信息源
- 每个情报源记录：URL 地址、来源名称、所属行业、分类标签、抓取频率、是否启用

**Step 2：支持 Excel 批量导入**

- 下载模板 → 填写 URL/名称/行业/分类 → 上传
- 也支持界面逐条手动添加

**Step 3：行业与租户自动匹配**

- 系统根据租户所属行业，自动将对应行业的情报推送到该租户的"情报中心"页面
- 行业情报严格按行业匹配，不会跨行业推送

#### 情报AI费用分摊

- AI处理一次，费用均摊给所有订阅该行业的租户
- 例：PCB行业有3个租户，一条情报的AI处理费用 ÷ 3

### 场景④：配置行业邮件模板

- **操作者**：平台运营
- **频率**：一次性 + 按需调整
- **前置条件**：无，可与其他 Phase 0 任务并行

#### 步骤

**Step 1：按行业创建官方模板**

为每个行业创建多套官方邮件模板，覆盖常见场景：
- 首次触达模板（自我介绍 + 产品优势）
- 跟进模板（第2封、第3封）
- 促成下单模板
- 节日问候模板

每个模板包含：
- 邮件主题
- 正文
- 变量占位符：`{{公司名称}}`、`{{联系人姓名}}`、`{{联系人职位}}`、`{{产品标签}}`

**Step 2：关联行业**

- 每个模板关联所属行业
- 租户入驻时，系统自动将对应行业的官方模板加入租户的模板库

#### 模板层级

| 层级 | 权限 | 归属 |
|------|------|------|
| 平台官方模板 | 只读（租户不可修改原始模板） | 所有同行业租户共享 |
| 租户自有模板 | 可增删改 | 租户私有 |

- 租户看到的模板库 = 官方模板 + 自有模板
- 租户可将官方模板"复制为自有模板"后修改

### 场景⑤：配置域名预热规则

- **操作者**：平台运营
- **频率**：一次性
- **前置条件**：无，可与其他 Phase 0 任务并行

#### 域名预热方案（⚠️ 已修正）

> ⚠️ **矛盾修正 #2**：原需求文档写固定天数阶梯（第1天50封，第2-3天100封...），已确认修正为**动态指标驱动**。

**核心机制**：6档阶梯作为参考，但晋升靠指标而非固定时间。

| 档位 | 日发送上限 | 晋升条件 |
|------|-----------|----------|
| 档位1 | 50封/天 | 初始档位 |
| 档位2 | 100封/天 | 送达率/退信率等指标达标 |
| 档位3 | 200封/天 | 送达率/退信率等指标达标 |
| 档位4 | 500封/天 | 送达率/退信率等指标达标 |
| 档位5 | 1000封/天 | 送达率/退信率等指标达标 |
| 档位6 | 4000封/天 | 送达率/退信率等指标达标（最高档位） |

**Step 1：配置动态预热策略**

- 设定每个档位的日发送上限
- 设定晋升指标阈值（送达率 ≥ X%、退信率 ≤ Y%）
- 设定每个档位的最低停留时间（如至少1天）
- 指标达标则自动升档，指标异常则自动降档

**Step 2：配置退信率告警阈值**

- 退信率超过阈值（如 5%）→ 系统自动降低该域名额度并告警通知平台运营
- 退信率严重异常 → 自动降档

#### 关键约束

- 域名预热规则 = 平台通用的一套策略（所有租户统一）
- 发信域名 = 按租户配置，每个租户有自己的域名
- 规则通用，域名私有

- 可随时增删模型、更换 API Key，对租户透明

**Step 2：指定各场景默认模型**

## 4. Phase 1 — 租户入驻

> 每新增一个客户执行一次。

### 场景⑦：创建租户 + 配置发信域名 + AI充值

- **操作者**：平台运营
- **频率**：每新增一个客户
- **前置条件**：Phase 0 已完成（含场景⑥ AI模型配置）；有新客户签约

#### 步骤

**Step 1：创建租户**

在管理后台"租户管理"→"新建租户"：
- 填写公司名称、所属行业（**单选一个行业**）、联系人、联系方式
- 设置初始管理员账号和密码
- 系统自动：
  - 创建数据隔离空间
  - **复制该行业当前版本的默认评分模板**到租户空间（快照机制）
  - 加载该行业的官方邮件模板

**Step 2：配置发信域名**

- 为该租户添加发信域名（单个租户可配多个域名）
- 录入域名（如 `mail.customer-company.com`）
- 配置 SPF、DKIM、DMARC 记录（指导客户操作或代为操作）
- 系统自动验证 DNS 配置
- 验证通过后，自动按平台通用预热规则（场景⑤）开始预热
- 每个域名独立预热、独立计算额度

**Step 3：创建租户团队账号**

- 直接为租户的团队成员创建账号密码
- 角色选择：管理员 / 业务员 / 只读观察者（3角色）
- 将账号清单发给租户管理员

**Step 4：为租户充值AI余额（首次）**

- 在"租户管理"→ 选中该租户 →"AI余额"中手动充值
- 录入充值金额（人民币），如首次充值 500 元
- 系统记录充值流水：时间、金额、操作人
- 租户登录后即可看到余额，直接使用AI功能

#### 充值方式

| 方式 | 阶段 | 说明 |
|------|------|------|
| 平台运营手动充值 | Phase 1（当前版本） | 在管理后台为租户充值 |
| 租户自助充值（微信/支付宝） | **推迟到后续版本** | Phase 1 不实现自助支付 |

#### 域名额度逻辑

- 每个域名的每日发送上限由预热进度自动决定
- 该租户所有发送计划共享其域名的当日额度
- 当日额度用完 → 所有计划自动暂停，次日继续
- 无"单计划上限"概念

### 场景⑧：租户首次登录与配置

- **操作者**：租户管理员
- **频率**：首次登录
- **前置条件**：场景⑦完成（账号已创建、域名已配或正在预热、AI余额已充值）

#### 步骤

**Step 1：首次登录**

- 用平台提供的账号密码登录
- 系统引导修改密码、补充公司详细信息

**Step 2：配置采集关键词（必填）**

- 管理员**必须**配置采集关键词，系统才能为该租户采集数据
- 示例：
  - 赵总（PCB企业）："multilayer PCB""heavy copper PCB""HDI board"
  - 刘总（另一PCB企业）："rigid-flex board""aluminum PCB""LED PCB"
- 关键词用于外贸通和腾道的直接采集（路径一），以及励销云的同行搜索（路径二）
- **多租户关键词重叠处理**：系统汇总所有租户的关键词，去重后统一调度采集，结果自动关联到所有配置了该关键词的租户

**Step 3：查看/调整评分规则（可选）**

- 系统已在入驻时复制了行业默认评分模板的快照
- 管理员可以：
  - 直接使用（推荐新客户先用）
  - 自定义调整（自由度最大）：
    - **维度**：可增删评分维度
    - **规则**：可修改每个维度的评分条件
    - **分值**：可调整每个条件对应的分值
- 修改后与平台默认模板完全脱钩

**Step 4：配置联系人选择规则**

管理员配置租户统一的联系人选择规则，决定每个公司默认联系谁：

- **基础机制**：保留 A/B/C/D 职位分级（按职位重要性预设分级）
- **叠加机制**：租户规则作为额外筛选条件叠加
  - 例如：只看 A/B 级中的采购部门
  - 例如：优先"采购经理""采购总监""技术总监"等决策角色
- 联系方式要求：如必须有邮箱
- 每个公司最多选择 N 个联系人（如默认 1 个）
- 系统根据规则自动为每个公司选定"默认联系人"
- 后续业务员可以针对单个公司手动调整

**Step 5：查看AI余额与消费（可选查看）**

管理员在"设置"中可以查看：

| 信息 | 说明 |
|------|------|
| 当前余额 | AI功能可用余额（人民币） |
| 消费明细 | 按功能分类：情报摘要消费 / 邮件生成消费 / 数据分析消费 / 评分LLM辅助消费 |
| 消费趋势 | 按日/周/月的消费趋势图表 |
| 充值记录 | 历史充值流水（平台充值） |

> Phase 1 不提供自助充值功能（推迟到后续版本）。

#### 配置完成后

- 域名可能还在预热，但业务员可以开始浏览公司列表、查看优选客户、准备模板
- 发送计划需等域名有额度后才能执行
- 采集任务将在下一个执行周期开始为该租户的关键词采集数据
- AI功能在余额充足时即可使用

### 场景⑫：创建并执行发送计划

- **操作者**：业务员 / 管理员 + 系统自动执行
- **频率**：核心流程
- **前置条件**：场景⑩有群组可选 + 场景⑪有模板可用 + 场景⑦域名有额度（三者缺一不可）

#### 步骤

**Step 1：新建发送计划**

- 点击"发送计划"→"新建"
- 填写计划名称（如"德国 A 级客户首次触达"）和说明

**Step 2：选择收件人（群组或公司列表）**

- **选择群组**：直接选择已创建的群组，群组内所有公司的默认联系人作为收件人
- **选择公司列表**：也可通过筛选条件临时圈定一批公司
- 当某公司有多个联系人时，使用该公司的默认联系人
- 系统实时显示收件人数量
- 自动排除：黑名单公司、已退订的联系人、待补全状态的公司

**Step 3：选择邮件模板**

- 从模板库选择（官方或自有）
- 可预览变量替换后的效果

**Step 4：配置发送策略**

| 配置项 | 说明 |
|--------|------|
| 发送时间窗口 | 按目标国家工作时间自动匹配（如德国 9:00-11:00 当地时间） |
| 发送间隔 | 30秒-2分钟随机 |
| 发送域名 | 选择已预热的域名（当日发送量跟该域名的当日额度走） |

**Step 5：配置序列邮件**

序列邮件是发送计划的**标准组成部分**（非可选）：

| 序列 | 触发条件 | 模板 |
|------|----------|------|
| 第1封 | 首次触达（立即发送） | 选择模板 A |
| 第2封 | 第1封发出后 N 天（如4天），收件人未回复 | 选择模板 B |
| 第3封 | 第2封发出后 N 天（如7天），仍未回复 | 选择模板 C |
| ... | 可继续添加 | 每一封选择不同模板 |

- 收件人在任何阶段回复 → 自动停止后续序列
- 最少1封，最多可配置多封

**Step 6：预览确认 → 草稿**

- 系统展示摘要：收件人数量、序列封数、使用域名
- 随机预览 3-5 封实际邮件内容
- 确认后进入"草稿"状态

**Step 7：启动执行**

- 点击"执行"，状态变为"执行中"

**Step 8：系统自动发送**

- 按目标国家工作时间窗口发送
- 替换变量（公司名、联系人名、职位、产品标签）
- 监控域名当日额度，达到上限 → 该域名下所有计划自动暂停，次日继续
- 记录每封邮件的发送状态
- 通过 EngageLab 回收投递状态

**Step 9：随时暂停/恢复**

- 业务员可随时暂停/恢复
- 执行中可追加收件人或修改后续序列模板

#### 关键约束

- 发送计划只管"发送"：不负责采集、不负责评分、不负责清洗

### 场景⑬：邮件监控与数据分析

- **操作者**：业务员 / 管理员
- **频率**：持续跟踪
- **前置条件**：场景⑫的发送计划已开始执行

#### 步骤

**Step 1：查看执行状态**

"邮件监控"页面：总发送量/今日量、发送进度、成功率/退信率、当前状态、域名剩余额度。

**Step 2：投递效果指标**

EngageLab 回传数据：触达率、打开率、点击率、回复率、退信率、退订率。

**Step 3：多维度筛选分析**

- **时间维度**：按日期范围筛选、按周/月汇总趋势、对比不同时段效果
- **业务维度**：
  - 按发送计划筛选
  - 按群组筛选
  - 按客户评级筛选（S/A/B/C/D 各级别的响应率对比）
  - 按国家/地区筛选
  - 按模板筛选（对比不同模板效果）
  - 按序列阶段筛选（第1封/第2封/第3封效果对比）
  - 按邮件状态筛选（已打开未回复 / 已回复 / 已退信）

**Step 4：下钻到公司维度**

- 在公司详情页增加"邮件"Tab
- 展示该公司所有邮件往来记录：发了几封、每封什么时候发的、什么状态、是否打开/点击/回复

**Step 5：回复邮件处理**

- 收到回复 → 标记"已回复" → 自动停止后续序列
- 回复内容可在系统内查看原文
- 继续一对一沟通引导到外部邮箱
- **接收机制**：待调研（需确认 EngageLab 是否支持 inbound 邮件解析）

**Step 6：AI 分析建议**

- 使用平台统一配置的数据分析模型
- 生成分析建议，如："德国打开率35%高于平均22%，建议增加德国比例""模板B回复率是模板A的3倍"
- 消耗租户AI余额
- 余额不足时"AI分析"按钮置灰并提示充值

## 6. 持续后台运行

> 系统自动任务，每天执行，租户无感。

### 后台任务A：数据自动采集与入库

- **触发条件**：场景①数据源已配置 + 至少有一个租户配置了采集关键词
- **执行频率**：每日定时
- **部署方式**：独立服务器，通过 **API调用** 与主系统通信（⚠️ 非消息队列）

#### 流程

**A1：汇总所有租户关键词**

- 系统汇总所有租户配置的采集关键词
- **去重后形成采集任务队列**
- 每个关键词标记来源租户（用于后续数据关联）
- 同一关键词被多个租户配置时，只采集一次，结果自动关联到所有相关租户

**A2：路径一 — 外贸通 + 腾道直接采集**

- 按关键词在外贸通和腾道搜索海外公司/采购商信息
- 按配置的爬取频率（如30秒间隔）控制请求速度
- 采集结果落入 `shared_companies`

**A3：路径二 — 励销云反查采集**

- 按关键词在励销云搜索中国同行公司 → 同行信息落入 `competitor_companies`
- 提取同行英文公司名 → 去外贸通和腾道检索其出口对象
- 获取精准客户列表落入 `shared_companies` 并标记为"精准客户"

**A4：清洗 → 去重 → 入库**

- 剔除无效数据 → 标准化
- 以**数据源ID为主键，公司名辅助**去重（⚠️ 已修正）
- 已存在则合并更新，不存在则新增
- 进入共享公司池，自动关联到对应租户

#### 采集计费

- 每个租户独立计费（即使数据源侧可去重/缓存）
- 采集费用**不计入AI消费**

---

### 后台任务B：情报自动采集

- **触发条件**：场景③行业情报源已配置 + 场景⑥ AI模型已配置
- **执行频率**：每日定时

#### 流程

**B1：按 URL 列表抓取**

- 从配置的行业情报源 URL 抓取最新内容

**B2：AI 处理**

- 使用平台统一配置的情报摘要模型生成摘要、提取关键词、分类标签
- AI处理一次，费用**均摊给所有订阅该行业的租户**
- 余额为0的租户：情报仅展示原文标题和链接，不做AI深度处理

**B3：按行业推送**

- 无人工审核，直接推送到行业匹配的租户情报中心页面

---

### 后台任务C：评分计算（T+1）

- **触发条件**：场景②评分模板已配置 + 后台任务A有新数据入库
- **执行频率**：每日定时（T+1）

#### 流程

**C1：识别待评分公司**

- 找出昨天（T-1日）新入库或数据有更新的公司
- 包括充值后需要补评的"待评分"公司

**C2：检查维度数据完整性**

- 只对维度数据齐全的公司进行评分
- 缺少关键评分维度数据的，标记为"待补全"，不参与评级

**C3：逐租户计算评分**

- 对每个租户，按该租户的评分规则（快照或自定义修改后的规则）计算评分
- 不同租户对同一公司可能有不同评分
- **纯规则维度**：直接计算，不消耗AI余额
- **LLM辅助维度**（如产品/行业匹配度）：调用AI判断，扣租户AI余额
- **余额为0的租户**：暂停该租户全部评分，新入库公司标记"待评分"，充值后统一补评

**C4：励销云路径特殊处理**

- 通过励销云反查路径获得的"精准客户"，直接标记为 S 级（最高级别）
- 不受常规评分计算影响

**C5：更新评级**

- 根据评分结果更新评级标签（S/A/B/C/D）
- 优选客户列表实时反映

---

### 后台任务D：域名额度监控

- **触发条件**：场景⑦域名已配置，有发送计划在执行
- **执行频率**：实时监控

#### 流程

**D1：实时统计发送量**

- 每发出一封邮件，更新该域名的今日已发送量

**D2：域名额度检查**

- 达到域名当日上限 → 该域名下所有发送计划自动暂停，次日继续

**D3：退信率监控**

- 退信率突然升高 → 自动降低域名额度（降档）→ 通知平台运营排查

**D4：预热进度推进**

- 按平台通用预热规则（场景⑤的动态指标驱动方案）推进
- 指标达标则自动升档，指标异常则自动降档
- 不依赖固定天数

- JWT Bearer 认证 + RBAC 权限控制
- API Key 仅平台级管理，不暴露给租户
- CORS 配置收紧（现有系统 CORS 全开，需修复）
