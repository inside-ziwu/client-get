场景 1：配置数据源渠道与账号 一次性 + 按需调整

前置条件：无。系统上线后第一件事。

平台运营 — 配置三个采集渠道的账号密码和渠道别名。注意：关键词由租户侧配置（见场景⑧），不在此处。

  1. 1添加采集渠道与别名
    在管理后台"数据源管理"中添加采集渠道，并设置渠道别名（对租户脱敏）：
    渠道别名编码用途
    外贸通A01按关键词直接搜索海外采购商/公司
    腾道B01按关键词搜索海关进出口数据、采购商
    励销云C01搜索中国同行 → 反查其出口对象 → 获取精准客户
    平台运营可自定义渠道别名，后续新增渠道时在此添加。
  2. 2配置渠道账号密码
    为每个渠道录入平台级账号密码，支持多账号轮换：
    • 外贸通：录入账号密码，支持配置多个账号方便切换
    • 腾道：录入账号密码，支持配置多个账号方便切换
    • 励销云：录入账号密码，支持配置多个账号方便切换
    账号密码集中在平台运营侧维护，方便在账号受限时快速切换。
  3. 3配置爬取频率
    设置爬取频率参数（控制对数据源网站的请求速度）：
    • 请求间隔：如 30 秒/次（避免被数据源封IP）
    • 每次批量上限：如单次最多抓取 100 条
    • 每日执行时段：如凌晨 02:00-06:00
  4. 4配置数据落库规则
    设定采集数据的落库逻辑（两条采集路径，三个数据库表）：
    • 路径一（外贸通 + 腾道 → 直接采集）：按租户关键词在外贸通和腾道搜索，搜到的海外公司信息直接落入"公司原始数据库"
    • 路径二（励销云 → 竞对反查）：按租户关键词在励销云搜索中国同行公司，搜到的同行信息落入"竞对公司原始数据库"；然后拿同行英文名去外贸通和腾道检索其出口对象，获得的精准客户列表同样落入"公司原始数据库"，但标记为"精准客户"（区别于路径一直接抓回来的数据）
    去重唯一键 = 客户公司名称（不是公司名+域名）
关键词由谁配？关键词由租户管理员在自己的后台配置（见场景⑧），不经平台运营审核。平台运营只负责维护渠道账号和爬取参数。系统会汇总所有租户的关键词，统一调度采集任务。

场景 2：配置行业评分模板 一次性 + 按需调整 V3.1 修订

前置条件：场景 ① 完成（知道有哪些数据字段可用于评分）。

平台运营 — 评分体系分两层：平台运营提供行业默认模板，租户入驻时复制一份快照到自己空间，之后可自由修改。

  1. 1创建行业默认评分模板（平台侧）
    在管理后台为每个行业创建 1 套默认评分模板。例如 PCB 行业默认 7 个维度：
    维度规则示例分值示例
    工厂性质贸易商 / 制造商 / 两者兼具10 / 30 / 25
    公司规模按员工数或注册资本区间5-20
    进出口数据有/无进口记录0 / 15
    进出口频次近12个月交易次数区间0-20
    联系人丰富度有效联系人数量区间0-15
    数据来源来源渠道编码5-15
    PCB供应商匹配度产品关键词匹配程度0-20
  2. 2设定默认评级区间
    定义总分对应的评级：
    • S级（精准）：通过励销云反查路径获得的客户，默认最高级别
    • A级（优质）：80分以上
    • B级（良好）：60-79分
    • C级（一般）：40-59分
    • D级（低优先）：40分以下
  3. 3平台运营可随时调整（仅影响后续新租户）
    平台运营可以随时调整行业默认模板的维度、规则和分值。但变更只影响之后新入驻的租户——已入驻的租户在入驻时已复制了一份模板快照到自己的空间，平台模板后续变更不会回溯影响他们（可以理解为每个租户拿到的是入驻那一刻的"副本"）。V3.1 快照复制机制
租户自定义自由度（场景⑧中操作）：租户拿到快照后，可以在此基础上自由修改——维度可增删、规则可改、分值可调，自由度最大。修改后与平台模板完全脱钩。快照+自由修改

场景 3：维护行业情报源 一次性 + 按需调整

前置条件：无。可与场景①②并行。

平台运营 — 维护各行业的情报信息源，行业匹配的租户自动看到采集清洗后的情报。

  1. 1按行业创建情报源列表
    为每个行业维护一组情报信息源。例如 PCB 行业的情报源包括：行业网站、新闻源、海关数据摘要、展会信息站点。每个情报源记录：URL 地址、来源名称、所属行业、分类标签、抓取频率、是否启用。
  2. 2支持 Excel 批量导入
    情报源支持通过 Excel 批量导入：下载模板 → 填写 URL、名称、行业、分类等字段 → 上传到系统。后续增删源时，修改 Excel 重新导入即可。也支持在界面上逐条手动添加。
  3. 3行业与租户自动匹配
    系统根据租户所属行业，自动将对应行业的情报推送到该租户的"情报中心"页面。例如 PCB 行业的情报只推送给 PCB 行业的租户，不会推给其他行业。
运行逻辑：系统每天自动从情报源 URL 抓取 → AI（平台统一配置的模型，见场景⑥）摘要分类 → 直接推送到行业匹配的租户情报中心。无人工审核环节。V3.2 恢复平台级

场景 4：配置行业邮件模板 一次性 + 按需调整

前置条件：无。可与其他 Phase 0 任务并行。

平台运营 — 平台按行业提供官方邮件模板，租户可直接使用或在此基础上自定义。

  1. 1按行业创建官方模板
    为每个行业创建多套官方邮件模板，覆盖常见场景：
    • 首次触达模板（自我介绍 + 产品优势）
    • 跟进模板（第2封、第3封）
    • 促成下单模板
    • 节日问候模板
    每个模板包含：邮件主题、正文、变量占位符（{{公司名称}}、{{联系人姓名}}、{{联系人职位}}、{{产品标签}}）。
  2. 2关联行业
    每个模板关联所属行业。租户入驻时，系统自动将对应行业的官方模板加入租户的模板库，租户可直接使用、复制后修改、或完全自建模板。
模板层级：平台官方模板（只读，所有同行业租户共享）+ 租户自有模板（可增删改，租户私有）。租户看到的模板库 = 官方模板 + 自有模板。

场景 5：配置域名预热规则（平台通用） 一次性

前置条件：无。可与其他 Phase 0 任务并行。

平台运营 — 域名预热规则是平台通用的，所有租户的域名统一使用同一套预热策略。

  1. 1配置通用预热递增策略
    设定新域名的预热递增规则（所有租户的新域名均适用）：
    • 第1天：50封/天
    • 第2-3天：100封/天
    • 第4-7天：200封/天
    • 第2周：500封/天
    • 第3周：1000封/天
    • 第4周起：根据退信率，最高 4000封/天
  2. 2配置退信率告警阈值
    设定自动保护规则：退信率超过阈值（如 5%）→ 系统自动降低该域名额度并告警通知平台运营。
域名预热规则 vs 发信域名：预热规则 = 平台通用的一套策略。发信域名 = 按租户配置，每个租户有自己的域名（见场景⑦）。规则通用，域名私有。

场景 6：配置统一AI大模型 一次性 + 按需调整 V3.2 新增

前置条件：无。可与其他 Phase 0 任务并行。

平台运营 — AI模型和API Key由平台统一配置和管理。租户不需要自己购买或管理API Key，只需有余额即可使用AI功能。

  1. 1添加可用AI模型
    在管理后台"AI配置"中添加可用模型和对应API Key：
    模型用途说明
    Google Gemini 2.5情报摘要、邮件生成、数据分析平台购买API Key，统一管理
    GLM 5（智谱）情报摘要、邮件生成、数据分析平台购买API Key，统一管理
    DeepSeek情报摘要、邮件生成、数据分析平台购买API Key，统一管理
    豆包（字节）情报摘要、邮件生成、数据分析平台购买API Key，统一管理
    可随时增删模型、更换API Key，对租户透明。
  2. 2指定各场景默认模型
    为不同AI使用场景指定默认模型（所有租户统一）：
    • 情报摘要：选择一个模型用于每日情报的摘要和分类
    • 邮件生成：选择一个模型用于AI生成邮件（业务员使用时可在平台提供的可用模型中切换）
    • 数据分析：选择一个模型用于邮件效果分析和建议
  3. 3配置AI计费单价
    设置AI功能的计费参数（计费单位为人民币）：
    • 每个模型的token→人民币换算比例（如：Gemini 2.5 = 0.01元/千token）
    • 平台运营可随时调整单价（调价后立即生效，影响后续消费）
    • 系统自动按实际token消耗换算为人民币金额，扣减租户余额
平台统一管理的好处：租户不需要了解API Key、token等技术细节。租户只关心两件事：①AI功能好不好用 ②余额够不够。平台运营负责技术选型、成本控制、模型升级。
💰 AI计费概览：AI功能按租户实际使用量计费（人民币），包括：情报AI摘要、邮件AI生成、数据AI分析。邮件发送和数据采集不计入AI消费。租户余额为0时，AI功能不可用，但不影响其他功能（发邮件、浏览数据等）。
Phase 1 — 租户入驻（每新增一个客户执行一次）

场景 7：创建租户 + 配置发信域名 + AI充值 运营操作 V3.1 修订 V3.2 修订

前置条件：Phase 0 已完成（含场景⑥ AI模型配置）。有新客户签约。

平台运营 — 为新客户创建账号并配置发信域名。不支持自助注册。

  1. 1创建租户
    在管理后台"租户管理" → "新建租户"：
    • 填写公司名称、所属行业（如"PCB"）、联系人、联系方式
    • 设置初始管理员账号和密码
    • 系统自动：创建数据隔离空间 + 复制该行业当前版本的默认评分模板到租户空间 + 加载该行业的官方邮件模板
    评分模板=复制快照，非引用
  2. 2配置发信域名
    为该租户添加发信域名（单个租户可配多个域名）：
    • 录入域名（如 mail.customer-company.com）
    • 配置 SPF、DKIM、DMARC 记录（指导客户操作或代为操作）
    • 系统自动验证 DNS 配置
    • 验证通过后，自动按平台通用预热规则（场景⑤）开始预热
    • 每个域名独立预热、独立计算额度
  3. 3创建租户团队账号
    直接为租户的团队成员创建账号密码（管理员角色 / 业务员角色），将账号清单发给租户管理员即可。
  4. 4为租户充值AI余额（首次）
    在"租户管理" → 选中该租户 → "AI余额"中为其手动充值：
    • 录入充值金额（人民币），如首次充值 500 元
    • 系统记录充值流水：时间、金额、操作人
    • 租户登录后即可看到余额，直接使用AI功能
    后续租户可自助在线充值（微信/支付宝），也可联系平台运营手动充值。V3.2 AI充值
域名额度逻辑：每个域名的每日发送上限由预热进度自动决定（如第1天50封，第2周500封）。该租户所有发送计划共享其域名的当日额度。当日额度用完 → 所有计划自动暂停，次日继续。无"单计划上限"概念。
💰 AI余额与充值：平台运营在创建租户时手动充值首笔AI余额。后续支持两种充值方式：① 平台运营在管理后台手动为租户充值 ② 租户自助通过微信/支付宝在线充值。所有充值记录可在管理后台和租户后台双向查看。V3.2

场景 8：租户首次登录与配置 租户操作 V3.1 修订 V3.2 修订

前置条件：场景 ⑦ 完成（账号已创建、域名已配或正在预热、AI余额已充值）。

租户管理员 — 首次登录，完成必要配置后开始使用。

  1. 1首次登录
    用平台提供的账号密码登录。系统引导修改密码、补充公司详细信息。
  2. 2配置采集关键词（必填）
    管理员必须配置采集关键词，系统才能为该租户采集数据。例如：
    • 赵总（PCB 企业）配置："multilayer PCB""heavy copper PCB""HDI board"
    • 刘总（另一 PCB 企业）配置："rigid-flex board""aluminum PCB""LED PCB"
    这些关键词会用于外贸通和腾道的直接采集（路径一），以及励销云的同行搜索（路径二）。系统汇总所有租户的关键词统一调度采集。
  3. 3查看/调整评分规则（可选）
    系统已在入驻时复制了行业默认评分模板的快照。管理员可以：
    • 直接使用（推荐新客户先用）
    • 自定义调整，自由度最大：
      • 维度：可增删评分维度（如不要"数据来源"维度，或新增"成立年限"维度）
      • 规则：可修改每个维度的评分条件（如把"≥10次/年"改成"≥5次/年"）
      • 分值：可调整每个条件对应的分值
    修改后与平台默认模板完全脱钩。快照副本，修改不影响其他租户
  4. 4配置联系人选择规则
    管理员配置租户统一的联系人选择规则，决定每个公司默认联系谁：
    • 优先职位：如优先"采购经理""采购总监""技术总监"等决策角色
    • 联系方式要求：如必须有邮箱
    • 每个公司最多选择 N 个联系人（如默认 1 个）
    系统根据规则自动为每个公司选定"默认联系人"。后续业务员可以针对单个公司手动调整。
  5. 5查看AI余额与消费（可选查看）
    管理员在"设置"中可以查看：
    信息说明
    当前余额AI功能可用余额（人民币）
    消费明细按功能分类：情报摘要消费 / 邮件生成消费 / 数据分析消费
    消费趋势按日/周/月的消费趋势图表
    充值记录历史充值流水（平台充值/自助充值）
    自助充值点击"充值" → 选择金额 → 微信/支付宝支付 → 余额实时到账
    AI模型由平台统一配置（见场景⑥），租户不需要管理API Key。业务员使用AI功能时只需关注余额是否充足。V3.2 AI余额可见+自助充值
配置完成后：域名可能还在预热，但业务员可以开始浏览公司列表、查看优选客户、准备模板。发送计划需等域名有额度后才能执行。采集任务将在下一个执行周期开始为该租户的关键词采集数据。AI功能在余额充足时即可使用。

场景 9：浏览公司列表、筛选目标客户 每日操作

前置条件：场景 ⑧ 完成（已登录+已配关键词）。后台采集任务已运行过至少一次。

业务员 / 管理员 — 在"公司列表"中浏览、搜索、筛选潜在客户。

  1. 1打开公司列表
    点击"公司列表"，看到共享公司池中所有清洗后数据。列表展示完整字段：
    字段名说明
    公司名称公司英文全称（唯一键）
    国家/地区公司所在国家和地区
    行业所属行业分类
    产品标签细分产品标签（如"汽车导航""行车记录仪"）
    公司成立时间公司注册/成立日期
    员工规模员工人数区间
    注册资本注册资本金额
    工厂性质贸易商 / 制造商 / 两者兼具

  2. 2多维度筛选
    按条件组合筛选：
    • 国家/地区（支持多选）

    • 进出口记录（有/无）
    • 进出口频次区间
    • 数据源编码（A01/B01/C01）
    • 数据标记（普通采集/精准客户）

    • 入库时间范围
  3. 3查看公司详情
    点击展开：基本资料、进出口记录摘要、联系人列表（含默认联系人标记）、产品标签、本租户下的评分和评级。
  4. 4手动添加公司

公司列表 vs 优选客户：公司列表 = 未经评分的"全量大池子"，适合探索。优选客户（场景⑩）= 评分后的"全量评分池"（默认显示所有级别），是主要工作台。

前置条件：评分已配置 + 系统已执行过 T+1 评分计算 + 联系人规则已配置。

业务员 / 管理员 — 业务员日常工作主页面。查看评分后的客户，按群组管理和发送。

  1. 1打开优选客户页面
    点击"优选客户"，看到所有已评分的公司列表，按评级排序。默认展示全部级别（S/A/B/C/D），可通过筛选器过滤。每个公司显示评分、评级标签和默认联系人。
  2. 2按评级和标签筛选
    筛选条件：按评级（S/A/B/C/D）、按产品标签、按联系状态（未联系/已发送/已回复/已加入群组）、按数据标记（普通采集/精准客户）。
  3. 3查看客户详情
    展开详情：评分明细（每维度得分）、联系人列表（标记默认联系人）、公司基本信息。可以针对单个公司手动调整默认联系人。
  4. 4创建和管理群组

    • 创建群组：如"德国 A 级客户""法国精准客户""2026Q1 新入库"
    • 添加到群组：筛选后批量勾选 → 加入指定群组

    • 群组发送：创建发送计划时直接选择群组作为收件人（见场景⑫）
    每个公司在群组中使用其"默认联系人"作为收件人。
  5. 5其他操作
    导出 Excel、修改标签、移入黑名单。
评分执行规则：
  • T+1 执行：今天入库的数据，明天执行评分计算
  • 仅评完整数据：只对维度数据齐全的公司进行评分，数据不全的标记为"待补全"不参与评级

业务员 / 管理员 — 使用平台官方模板或自建模板。

  1. 1进入模板库

  3. 3新建自有模板 — 手动编写

    • 生成 2-3 版本供选择，选中后可手动微调
    AI模型=平台统一配置
  5. 5保存模板
    保存后可编辑、复制、删除。租户自有模板属于租户私有。

场景 12：创建并执行发送计划 核心流程

前置条件：场景 ⑩ 有群组可选 + 场景 ⑪ 有模板可用 + 场景 ⑦ 域名有额度。三者缺一不可。

业务员 / 管理员系统自动执行 — 系统核心价值。选群组 → 选模板 → 配策略 → 配序列 → 自动发送。

  1. 1新建发送计划
    点击"发送计划" → "新建"，填写计划名称（如"德国 A 级客户首次触达"）和说明。
  2. 2选择收件人（群组或公司列表）
    选择收件人来源：
    • 选择群组：直接选择已创建的群组（如"德国 A 级客户"），群组内所有公司的默认联系人作为收件人
    • 选择公司列表：也可以通过筛选条件临时圈定一批公司，每个公司使用其默认联系人
    • 当某公司有多个联系人时，使用该公司的默认联系人（由租户统一规则决定，或业务员在优选客户页面手动指定过的）
    系统实时显示收件人数量。自动排除：黑名单公司、已退订的联系人。
  3. 3选择邮件模板
    从模板库选择（官方或自有），可预览变量替换后的效果。
  4. 4配置发送策略
    • 发送时间窗口：按目标国家工作时间自动匹配（如德国 9:00-11:00 当地时间）
    • 发送间隔：30秒-2分钟随机
    • 发送域名：选择已预热的域名（当日发送量跟该域名的当日额度走）
  5. 5配置序列邮件
    配置多轮跟进序列（不是可选，序列邮件是发送计划的标准组成部分）：
    • 第1封：首次触达（立即发送），选择模板 A
    • 第2封：跟进（第1封发出后 N 天，如4天），如果收件人未回复，选择模板 B
    • 第3封：再次跟进（第2封发出后 N 天，如7天），如果仍未回复，选择模板 C
    • 每一封选择不同模板
    • 收件人在任何阶段回复 → 自动停止后续序列
    最少1封，最多可配置多封序列。
  6. 6预览确认 → 草稿
    系统展示摘要：收件人数量、序列封数、使用域名、随机预览 3-5 封实际邮件内容。确认后进入"草稿"。
  7. 7启动执行
    点击"执行"，状态变为"执行中"。
  8. 8系统自动发送
    系统后台自动执行：
    • 按目标国家工作时间窗口发送
    • 替换变量（公司名、联系人名、职位、产品标签）
    • 监控域名当日额度，达到该域名当日上限 → 该域名下所有计划自动暂停，次日继续
    • 记录每封邮件的发送状态
    • 通过 EngageLab 回收投递状态
  9. 9随时暂停/恢复
    业务员可随时暂停/恢复，执行中可追加收件人或修改后续序列模板。
发送计划只管"发送"：不负责采集、不负责评分、不负责清洗。只做一件事：按选好的群组、选好的模板、配好的策略和序列，自动发邮件。

场景 13：邮件监控与数据分析 持续跟踪

前置条件：场景 ⑫ 的发送计划已开始执行。

业务员 / 管理员 — 实时监控效果，多维度分析数据，优化策略。

  1. 1查看执行状态
    "邮件监控"页面：总发送量/今日量、发送进度、成功率/退信率、当前状态、域名剩余额度。
  2. 2投递效果指标
    EngageLab 回传数据：触达率、打开率、点击率、回复率、退信率、退订率。
  3. 3多维度筛选分析
    支持从多个维度筛选和分析邮件数据：
    • 时间维度：按日期范围筛选、按周/月汇总趋势、对比不同时段效果
    • 业务维度：
      • 按发送计划筛选
      • 按群组筛选
      • 按客户评级筛选（S/A/B/C/D 各级别的响应率对比）
      • 按国家/地区筛选
      • 按模板筛选（对比不同模板的效果）
      • 按序列阶段筛选（第1封/第2封/第3封的效果对比）
      • 按邮件状态筛选（已打开未回复 / 已回复 / 已退信）
  4. 4下钻到公司维度
    在公司详情页增加"邮件"Tab，展示该公司所有邮件往来记录：发了几封、每封什么时候发的、什么状态、收件人是否打开/点击/回复。从公司维度看邮件效果。
  5. 5回复邮件处理
    收到回复 → 标记"已回复" → 自动停止后续序列。回复内容可在系统查看。Phase 1 后续一对一沟通引导到外部邮箱。
  6. 6AI 分析建议
    AI（使用平台统一配置的数据分析模型，见场景⑥）分析数据给出建议：如"德国打开率35%高于平均22%，建议增加德国比例""模板B回复率是模板A的3倍""第2封跟进邮件的转化率最高""周二上午打开率最高"。AI=平台统一模型
💰 AI消费提示：AI分析建议会消耗AI余额。每次分析按实际token消耗计费。余额不足时"AI分析"按钮置灰并提示充值。V3.2
持续后台运行 — 系统自动任务（每天执行，租户无感）

后台任务 A：数据自动采集与入库 每日执行

前置条件：场景 ① 数据源已配置 + 至少有一个租户配置了采集关键词。

系统定时任务 — 部署在独立服务器上，与主应用服务器分离，避免采集任务影响业务系统性能。

  1. A1汇总所有租户关键词
    系统汇总所有租户配置的采集关键词，去重后形成采集任务队列。每个关键词标记来源租户（用于后续数据关联）。
  2. A2路径一：外贸通 + 腾道直接采集
    按关键词在外贸通和腾道搜索海外公司/采购商信息，按配置的爬取频率（如30秒间隔）控制请求速度。采集结果直接落入"公司原始数据库"。
  3. A3路径二：励销云反查采集
    按关键词在励销云搜索中国同行公司 → 同行信息落入"竞对公司原始数据库" → 提取同行英文公司名 → 去外贸通和腾道检索其出口对象 → 获取精准客户列表落入"公司原始数据库"并标记为"精准客户"。
  4. A4清洗 → 去重 → 入库
    剔除无效数据 → 标准化 → 以"客户公司名称"为唯一键去重 → 已存在则合并更新，不存在则新增 → 进入共享公司池。
独立服务器部署：采集任务CPU和网络消耗大，部署在独立服务器上，避免影响业务系统的API响应和用户体验。通过消息队列与主系统通信。

后台任务 B：情报自动采集 每日定时 V3.2 修订

前置条件：场景 ③ 行业情报源已配置 + 场景 ⑥ AI模型已配置 + 租户AI余额充足。

系统定时任务 — 从情报源 URL 抓取 → AI 摘要分类 → 推送到行业匹配的租户情报中心。

  1. B1按 URL 列表抓取
    从配置的行业情报源 URL 抓取最新内容。
  2. B2AI 处理
    使用平台统一配置的情报摘要模型（场景⑥）生成摘要、提取关键词、分类标签。AI处理消耗对应租户的AI余额。余额为0的租户，情报仅展示原文标题和摘要，不做AI深度处理。AI=平台统一模型，消耗租户余额
  3. B3按行业推送
    无人工审核，直接推送到行业匹配的租户情报中心页面。

后台任务 C：评分计算（T+1） 每日定时

前置条件：场景 ② 评分模板已配置 + 后台任务 A 有新数据入库。

系统定时任务 — 对昨天入库的公司执行 T+1 评分计算。

  1. C1识别待评分公司
    找出昨天（T-1日）新入库或数据有更新的公司。
  2. C2检查维度数据完整性
    只对维度数据齐全的公司进行评分。如果某公司缺少关键评分维度的数据（如没有进出口记录字段），标记为"待补全"，不参与评级。
  3. C3逐租户计算评分
    对每个租户，按该租户的评分规则（入驻时的快照或自定义修改后的规则）计算评分。不同租户对同一公司可能有不同评分。快照/自定义规则
  4. C4励销云路径特殊处理
    通过励销云反查路径获得的"精准客户"，直接标记为 S 级（最高级别），不受常规评分计算影响。
  5. C5更新评级
    根据评分结果更新评级标签（S/A/B/C/D），优选客户列表实时反映。

后台任务 D：域名额度监控 实时

前置条件：场景 ⑦ 域名已配置。有发送计划在执行。

系统实时监控 — 监控每个域名的发送量、退信率，执行额度限制和预热推进。

  1. D1实时统计发送量
    每发出一封邮件，更新该域名的今日已发送量。
  2. D2域名额度检查
    达到域名当日上限 → 该域名下所有发送计划自动暂停，次日继续。
  3. D3退信率监控
    退信率突然升高 → 自动降低域名额度 → 通知平台运营排查。
  4. D4预热进度推进
    按平台通用预热规则（场景⑤）逐日递增域名额度，退信率正常才推进。
