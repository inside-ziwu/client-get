# ClientGet · B 实例运营后台操作手册

> **实例**:`instance_b` ｜ **登录账号**:`sales08@xxhpcb.com` ｜ **登录地址**:B 实例管理端(向 IT 确认具体网址) ｜ **适用范围**:仅 B 实例,与其他实例数据隔离 ｜ **内容截至**:2026-07-06

面向 B 实例运营人员:从配置采集账号,到开通一个客户、配好发信域名并交付。照着做即可,遇到的每个坑都已标注。

> **文档来源**:依据代码逻辑(5 路子系统排查)与生产库实际配置整理。系统会更新,操作若与本手册不符,以后台实际界面为准,并同步反馈更新本文档。可视化版本见对应 Artifact。

## 00 · 开始之前:三件必须先懂的事

### 1 · 你登录的就是 B 实例,系统自动隔离

你在这个后台创建、查看、修改的**一切**(数据源、AI、预热规则、客户、员工)都只属于 B 实例。系统按你登录的账号自动隔离——界面上**没有、也不需要**「选择实例」的地方,你永远看不到其他实例的数据。唯一要保证的是:**登录的是 B 实例的后台网址**(连错网址会进到别的实例,这时找技术检查前端配置)。

### 2 · 后台里的「用户」= 你的客户公司

> **术语对照**:后台左侧的「**用户管理**」、按钮「**创建用户**」,指的是**开通一个客户公司**(系统内部叫「租户」)。一个「用户」= 一家客户公司,不是一个人。别和「客户公司里的登录账号 / 团队成员」混淆。

### 3 · B 实例现在的状态(先看结论)

大部分平台配置已由初始化脚本备好,**唯一空缺、也是你上手第一件要做的事:给 3 个数据源配采集账号**——没有账号,采集跑不起来。

| 采集账号 | **0** | 🟠 待你配 | 3 个源都还没账号 |

## 01 · 平台准备:开客户之前先备好

下面 ②③④ 是「平台级」配置,通常一次性做好、所有客户共用。**② 数据源账号是当前的空缺,必须先补;③ AI 和 ④ 预热已就绪,了解怎么看、怎么调即可。**

## 02 · 配数据源采集账号 🟠 当前空缺 · 优先做

「数据源」是系统去海外抓公司数据的第三方平台。B 实例已经定义好 3 个源,但**一个采集账号都还没配**——这一步不做,采集就没有数据。

| 数据源 | 别名 | 用途 | 配账号时要填 |
|---|---|---|---|
| **外贸通** | `A01` | 关键词直接搜索海外公司 | Cookie、User Agent |
| **腾道** | `B01` | 海关采购商数据搜索 | API Key、Endpoint |
| **励销云** | `C01` | 同行反查精准客户 | Token、企业 ID |

### 操作步骤

1. **进入「数据源」页** — 左侧菜单进入**数据源**,会看到已有的 3 个源。
2. **给某个源添加采集账号** — 在目标源那一行点**「凭证」**(钥匙图标),打开凭证面板,点新增。按这个源的类型填对应字段(见上表),再填:
   - **账号编号**、**用户名**、**Secret / 上表的专属字段**
   - **轮换顺序**:多个账号轮流用时,从 0 开始依次 0、1、2……
   - **每日额度**:该账号每天最多调用多少次(可留空)
   - 勾选**启用**
   - 保存后 Secret 列显示成掩码(加密存储),即为成功。
3. **需要多账号就重复添加** — 同一个源可配多个账号轮流采集,轮换顺序设不同值。修改已有账号时,**Secret 留空表示不改动原密钥**。

> **⚠️ 坑 · 腾道命名不一致**:系统里「腾道」在不同地方有两个写法(`tengdao` 与 `tendata`),历史遗留导致。如果腾道账号配好了、采集却取不到,**把这条交给技术核对**:数据源里腾道的类型值,要和采集程序认的值一致(采集程序用的是 `tendata`)。外贸通、励销云无此问题。

> **ℹ️ 小提示**:数据源本身**不能删除**(只能改用途 / 停用)。真正决定能不能采集的是「账号」,不是数据源条目。

## 03 · AI 配置 ✅ 已就绪 · 了解即可

「AI 配置」页管两件事:**模型库**(有哪些可用模型)和**场景默认**(评分 / 邮件生成 / 情报摘要 / 数据分析 各用哪个模型)。B 实例已配好 5 个模型、4 个场景默认,一般不用动。

> **⚠️ 重点 · 这里没有填密钥的地方**:AI 配置页只登记「用哪个模型」,**没有 API 密钥输入框**。真正的 AI 密钥(OpenRouter Key)是**每个客户单独配的**——在客户详情页的「OpenRouter」标签里填(见 ⑤ 开通客户 · 第 3 步)。想给某客户开通 AI,去那里配他自己的 Key。

> **ℹ️ 据实说明 · 现在别在选模型上花时间**:目前系统**尚未接入真正的 AI 生成**,场景模型主要用于「校验有可用模型 + 用量记账」,**换更强的模型暂时不会改变实际输出效果**。保持默认即可,不用向客户承诺「换了更强模型效果更好」。

如需增改模型:「添加模型」填 **显示名称、Provider(填 `openrouter`)、Model ID**(如 `google/gemini-2.5-flash`)、启用。场景默认在页面下方,每个场景一个下拉,选中即时保存。注意:**停用 / 删除仍被某场景使用的模型前,要先把那个场景改绑到别的模型**,否则该场景会「查无可用模型」报错。

## 04 · 预热规则 ✅ 已就绪 · 按需调

「预热规则」控制**新发信域名每天最多发多少封**——新域名从低量开始、逐档养起来,避免被判垃圾邮件。B 实例已有 1 条「默认预热规则」并已激活,含多个档位(每档一个每日上限)。

- 一条规则 = 一套「档位表」;每个档位规定**该档每天上限**(daily_limit)。域名挂在某个档位上,就按那个档位的上限发。
- 页面在「**预热规则**」菜单,可改规则名、退信预警率,以及**增删档位**;改完点保存(整包覆盖保存)。

> **⚠️ 两个最容易误解的点**
> 1. **不会自动升档。** 档位里的「最少停留天数、送达率要求」等只是参考值,系统**不会自动**把域名提到更高档——需要你观察域名健康后,**手动**去客户域名里调高档位。
> 2. **每个实例只能有一条生效规则。** 改这条规则会影响 B 实例下所有客户的域名策略,谨慎改。

## 05 · 开通一个客户:完整流程

这是最核心的流程。顺序:**建客户 → 配发信域名 → 配该客户 AI 密钥 →(可选)加团队 → 交付**。开始前确认 ② 数据源账号、④ 预热规则已就绪。

### 第 1 步 · 创建客户

「用户管理」→「创建用户」,填写:

- **\*名称**(客户公司名)
- **\*行业** — 决定系统给客户复制哪套评分 / 邮件模板,**务必和平台模板的行业名写法完全一致**
- **\*管理员邮箱 / 管理员姓名 / 管理员密码**(密码 ≥ 8 位)— 这是客户登录自己后台的账号
- 联系人、电话选填;**Slug(网址标识)自动生成,建后不可改**

提交后系统**自动完成**:建好客户的登录账号(首次登录强制改密)、按行业复制评分模板和邮件模板、建默认联系人规则。

> **ℹ️ 注意**:行业名对不上平台模板时——评分会用系统内置默认、**邮件模板会是空的(不报错、静默为空)**,建好后记得去详情检查邮件模板。密码只校验长度、不校验复杂度,请自行设强密码。

### 第 2 步 · 配发信域名

打开该客户**详情 →「域名」标签 → 添加域名**:填域名、发件邮箱,并从下拉**选一个预热档位**(下拉里就是 ④ 里配的档位,如「档位 1 · 每日 N 封」)。一个客户可加多个域名。

> **⚠️ 坑 · 「验证」按钮是内部标记,不代表真能发信**:域名列表里的**「验证」只是把状态改成「已验证」,不做真实 DNS 检查、也不通知 EngageLab**。要真正能发信,必须**先在 EngageLab 后台完成这个域名的 DNS 认证**(SPF / DKIM / DMARC)。**点了「验证」≠ 真的能发。** 顺序应是:EngageLab 侧做好 DNS → 再点验证。

> **🟠 前提**:加域名时如果档位下拉是空的,说明**还没有激活的预热规则**——回到 ④ 确认规则已激活。

### 第 3 步 · 配该客户的 AI 密钥(需要 AI 时)

详情 →「**OpenRouter**」标签 → 填这个客户自己的 OpenRouter Key(可刷新查余额)。**每个客户用自己的 Key / 额度**,不填则该客户的 AI 功能不可用。

### 第 4 步 · 加团队成员(可选)

详情 →「团队」标签,给客户公司添加成员账号,角色可选 **admin / operator / viewer**,并设初始密码。

### 第 5 步 · 交付给客户

详情 →「基础信息」里复制**「后台管理地址」**。把**地址 + 管理员邮箱 + 初始密码**交给客户;客户首次登录会被**强制改密**。开通完成。

> **ℹ️ 如果「创建失败」但没说原因**:后台的报错提示比较笼统,多半是字段问题(如行业名 / 邮箱格式)。排查不了时,把时间点告诉技术,让他们看后端日志的具体错误码。

## ★ 坑速查

现象 → 原因 / 处理。遇到异常先对照这张表。

| 现象 | 原因 / 处理 |
|---|---|
| 采集完全没数据 | 数据源**没配采集账号**(B 实例初始为 0)或账号未启用 → 见 ② |
| 唯独腾道采不到 | `tendata` / `tengdao` 命名不一致 → 交技术核对类型值 |
| 加域名时档位下拉是空的 | 没有**激活的预热规则** → 回 ④ 激活 |
| 客户建好但邮件模板是空的 | 创建时**行业名没对上**平台邮件模板(静默为空)→ 用一致的行业名,或到详情补模板 |
| 域名显示「已验证」却发不出去 | EngageLab 侧 **DNS 认证没做**;后台「验证」只是内部标记 → 去 EngageLab 完成认证 |
| 域名发着发着停了 | 当天**预热档位上限到了**(次日按北京时间重置),或需要你**手动升档** |
| 换了更强的 AI 模型却没变化 | 目前**无真实 AI 推理**,属预期 → 保持默认即可 |
| 登进去看到别家公司的数据 | 前端**连错了后端实例** → 立刻停手找技术检查 |
| 要新增一个 B 实例后台管理员 | 后台**没有此入口**,需运维跑初始化脚本;且管理员邮箱**全局唯一**,不能和其他实例重复 |

### 附:技术侧关键事实(供 IT / 排障参考,非员工必读)

- **实例判定**:后端靠环境变量 `CLIENTGET_INSTANCE_ID=instance_b` 决定实例;前端 admin 靠「构建时注入的后端地址」隐式决定,连错地址会进错实例。
- **凭证加密**:数据源凭证、客户 OpenRouter Key 均用 Fernet 对称加密(密钥来自 `DATA_SOURCE_ENCRYPTION_KEY`);该密钥变更会导致存量密文无法解密。
- **实例隔离范围**:平台配置与客户数据按 `instance_id` 隔离;底层已采集 / 清洗的公司原始数据池跨实例共享(设计如此,不影响配置与触达隔离)。
- **新增管理员**:仅能由运维运行 `backend/scripts/init_instance.py`(需 `INIT_ADMIN_EMAIL` / `INIT_ADMIN_PASSWORD` / `CLIENTGET_INSTANCE_ID`)创建;`platform_users.email` 全局唯一。
