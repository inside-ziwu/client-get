# 动态源是实例内的行业级资产，不是租户配置

行业动态的动态源（站点 / feed 清单及其名称、类别、语种与解析规则）由开发随仓库种子按实例、按行业维护一套，该实例的平台管理员只做启停与监控，该实例内同行业的租户自动可见；不在租户级保存副本，也不跨实例共享（Instance A 配置的源对 Instance B 不生效）。曾考虑租户私有配置（每租户一份）与"行业级 + 租户可追加"两种归属方案，以及跨实例全局一份的范围方案：租户私有让同实例第二个同行业租户接入时要重复整套配置；"租户可追加"在没有任何租户提出自定义需求时属于预留；跨实例全局一份与「平台级表显式过滤 `instance_id`」的红线冲突，且两实例本就可能需要不同的源清单。实例内行业级与平台已有的"按行业配置评分模板、邮件模板"模式同构。2026-08-23 拍板（grill 第一轮 Q2、第二轮 Q10、更正轮 Q23）。

## Consequences

- 首批只在 Instance A 配置 13 个 PCB 站（CPCA 拆两行，共 14 条），A 实例内全部 PCB 租户上线即可见；Instance B 暂不配置，其租户看到的是空态页面。
- 动态源与动态均带 `instance_id`；每实例各自运行抓取循环，以实例级 advisory lock 互斥（与客户池修复循环同一模式）。
- 动态源的类别与语种随源配置，动态继承，不在条目级维护。
- 将来若有租户需要私有源，再以"行业级 + 租户追加"扩展，不改本决策。
