# local-docs-raw · 本地原始需求文档收件箱

> **目的**：让用户把本地散落的需求文档**拷贝**（不剪切）到这里集中查阅，作为 V3 Target Spec 的输入材料。
> **关联**：[`_control/v3/00-v3-target-spec.md`](../../v3/00-v3-target-spec.md)

## 1. 应该拷贝什么

| 类型 | 例子 | 优先级 |
| --- | --- | --- |
| 业务流程图 | 流程图 / 时序图 / 状态图 | 高 |
| 产品需求文档 | PRD、功能列表、用户故事 | 高 |
| UI 设计稿 | Figma 导出 / 截图 / 原型链接 | 中 |
| 客户/业务方访谈记录 | 访谈纪要、对话记录 | 中 |
| 原始竞品分析 | 截图、笔记 | 中 |
| 老版本 V1/V2 的需求 | 仅作参考，**不**作为 V3 实现依据 | 低 |

## 2. 操作规则

- ✅ **拷贝（cp）**，不剪切（mv）
- ✅ 原文件保留在原位置不动
- ✅ 文件名保持不变（如有冲突，加来源前缀，如 `notion-2026-04-30-PRD.md`）
- ❌ 不要在这里直接编辑文件——这是只读收件箱
- ❌ 不要拷贝包含 secret value 的文件（数据库连接字符串、API key、密码等）；如有需要，先脱敏

## 3. 拷贝完成后

- 在本目录下加一份 `INDEX.md`，列出每个文件的来源、类型、一句话摘要
- 通知 AI："`_control/inputs/local-docs-raw/` 已就绪，请基于这些材料整理 V3 Target Spec"
- AI 会读这些文件 + 已有的 [`docs/`](../../../docs/) 中标 `[BASELINE?]` 的活跃文档（[`02-docs-index.md`](../../02-docs-index.md) §1）综合提炼草稿

## 4. 当前状态

- 文件数：0（占位）
- 用户责任：拷贝输入材料

## 5. 不要在这里放

| 类型 | 应放到 |
| --- | --- |
| 数据库 schema / dump | [`../database/`](../database/)（已建索引） |
| Sealos 应用配置 | [`../sealos/`](../sealos/) |
| 测试租户/邮箱/采集源 | [`../test-data/`](../test-data/) |
| 已经在 docs/ 里的文件 | 不要拷贝；直接在 V3 Target Spec 里引用 [`docs/...`](../../../docs/) 路径即可 |
