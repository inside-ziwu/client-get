## 1. V3 一句话目标

让 **PCB 外贸厂老板**（租户）在 ClientGet 平台上完成完整的 **"采集 → 客户库 → 邮件营销"** 业务闭环——首次配置完成后，租户从客户库勾选目标公司、新建邮件计划、按预热档位发送，**全程无需运营介入**；运营仅在 2 个节点参与：**租户创建** + **首采启动**。

## 2. V3 服务谁

| 角色 | 描述 |
| --- | --- |
| **平台运营（admin）** | 平台管理员；管理租户、数据源凭证、EngageLab 域名 + DNS、首采启动、配置评分模板与联系人分类规则 |
| **租户用户**（**PCB 外贸厂**老板及其团队）| B2B PCB 外贸企业用户；自己配关键词、看客户、发邮件 |

## 3. V3 必须交付的 4 项业务能力

| # | 能力 | 含义 |
| --- | --- | --- |
| **R-1** | Sealos 已部署的 4 单元功能完整可用 | backend / admin / tenant / PostgreSQL 已上线，V3 后这 4 个的功能都正常工作 |
| **R-2** | 反推采集闭环 | 励销云 stage 1（中国同行）+ 腾道 stage 2（海外买家反查）跑通 |
| **R-3** | 完整邮件投递流程 | 配域名 → 创建邮件计划 → 真实发送 → 状态追踪 全链路 |
| **R-4** | 上线到 Sealos 生产环境 | 应用 + 数据库都跑在 Sealos，对真实租户开放使用 |

## 4. V3 业务流程闭环

```
[销售签约]                                                              [线下]
   ↓
[运营在 admin 端创建租户]
   （创建表单同步含：发件域名 + 起始预热档位）
   ↓
[运营配置域名 DNS 记录（SPF / DKIM / DMARC），完成 EngageLab 域名验证]
   ↓
[运营把账号信息线下交给租户]
   ↓
[租户登录 → 配 OpenRouter API key]
   ↓
[租户配关键词]
     ├─ 已采过 → 系统自动复用历史数据，租户立即看到客户
     └─ 未采过 → 运营在 admin 端启动首采
                    └──→ 反推路径：励销云搜中国同行 → 腾道反查海外买家
                              ↓
                         清洗去重合并 → 干净数据库 → 分发到所有命中租户
   ↓
[租户在客户库浏览]
   ↓
   ├─ 私有操作：精选（加入群组）/ 拉黑 / 调评分 / 备注 / 标签
   ↓
[租户勾选客户 → 新建邮件计划]
   ↓ 目标自动筛选（按 UC-08 联系人优先级规则，取每公司符合条件的所有联系人）
   ↓ 选序列结构（单封 / 多步骤含间隔天数）
   ↓ 选内容来源（租户模板 / 平台模板 / AI 生成 / 直接现写）
   ↓ 选启动方式（手动 / 定时）
   ↓
[Sending Worker 调 EngageLab 真实发送 → 按预热档位限速]
   ↓
[客户收到邮件，回复到租户自己邮箱]（回信不经平台）
   ↓
[V3 主链路终点：邮件已真实发出并写入投递状态]
```

## 5. V3 核心业务规则

### 5.1 关键词

- 仅英文；归一规则：大小写无关 + 去空格 + 去标点（`PCB-board` = `pcb board` = 同一关键词）
- 配置者：租户自己
- 数量上限：无
- **跨租户复用**：A 租户已采过的关键词，B 租户配同关键词时**立即看到 A 当年采到的全量历史数据**（零等待）

### 5.2 采集

- **数据源**：励销云（反推 stage 1）+ 腾道（反推 stage 2）
- **每日上限**：1000 条 / 数据源 / 天（HTTP 爬取风控约束）
- **数据流**：`原始库 → 清洗合并 → 干净数据 → 分发到命中租户`
- **励销云数据**：仅作 stage 2 输入（中国同行清单），**不进干净库**，租户永不可见
- **干净库唯一来源**：腾道（V3 期间客户库全部为反推产出的精准客户）
- **多租户共享**：凡命中关键词的租户都看到同一干净客户

### 5.3 客户库

- 客户列表 1 行 = 1 公司（不论命中几个关键词）
- 来源标签：**精准**（V3 期间客户库全部为精准）
- **10 项筛选**（客户列表 + 精选列表共用同一筛选组件）：
  - 多选 OR：国家 / 行业细分 / 产品标签 / 数据来源
  - 档位筛：成立时间 / 注册资金 / 公司规模 / 进出口额 / 进出口次数 / **联系人数量**
  - 联系人数量档位：`0 / 1-3 / 4-10 / 11-30 / >30`
- **双层评分**：
  - 第 1 层（系统默认等级）：精准 = 最高
  - 第 2 层（多维加权）：**平台运营按行业配模板**（含维度 / 档位 / 分值映射 / 默认权重），**租户仅调权重**
  - PCB 行业默认 7 维：工厂性质 / 工厂规模 / 进出口额 / 进出口次数 / 联系人（含采购）/ 数据来源 / PCB 供应商
  - 等级 S/A/B/C/D 阈值 `90+ / 70-89 / 50-69 / 30-49 / <30`
  - 档位外 / 数据缺失：兜底 0 分
- **租户私有状态层**（其他租户不可见）：
  - 是否在群组里（精选）
  - 是否拉黑
  - 租户级评分调整
  - 私有备注 / 标签

### 5.4 邮件营销

- **发件邮箱**：EngageLab 通道 + 租户自有域名（如 `marketing@abc.com`）
- **域名验证 + 预热档位**：在 admin 端创建租户时同步配置——**DNS 记录由平台运营配置**（SPF / DKIM / DMARC）；起始预热档位由运营基于域名状态选择
- **回信路径**：客户回信回到租户自己的邮箱（**不经平台**）
- **发送速率**：受平台预热档位统一约束（租户不能突破）
- **邮件状态**：联系人级 4 态（未开始 / 投递中 / 投递完成 / 已取消）
- **投递监控**（D-041，2026-05-06 决策）：以 EngageLab 回写为准，至少呈现 6 项指标——**发送量 / 送达率（含送达分级：软退信 / 无效邮箱）/ 独立打开率（含开信追踪）/ 软退信明细 / 举报垃圾邮件 / 退订**；UI 见原型 `_control/v3/mockups/tenant-email-monitor.html`
- **联系人职位分类规则**：
  - **平台运营统一配置**（admin 端 `admin/contact-classification`），所有租户继承使用，租户无配置 UI
  - 4 层模型：**等级**（admin 可增删，每级带"是否投递"开关）→ **类别**（如"老板/创始人"，给 UI 分组+报表用）→ **关键词**（如 owner/founder/CEO/...）
  - 匹配规则：联系人 `position` 切词后做集合交集；命中多关键词 → 取**最高等级**；未命中 → **不投递**
  - 例：`A 级（投递）`：老板/创始人/高管 / 采购决策；`B 级（投递）`：技术工程；`X 级（不投递）`：销售/HR/财务/法务
  - 邮件计划新建时**自动**取该公司所有等级"is_sendable=true"的联系人
  - 不限每公司联系人数（投递等级全发）
  - 多步骤序列跟进时，第 N 轮发同公司**未发过的其他联系人**（不重复发同一人）
- **邮件计划结构**：
  - 单封 OR 多步骤序列（每步自定义间隔天数）
  - 序列按时间表完整推进
  - 内容来源：租户模板 / 平台模板 / AI 生成 / 直接现写（4 选 1）

### 5.5 部署

Sealos 集群上跑 8 个部署单元：
- PostgreSQL（数据库）
- clientget-backend / clientget-admin / clientget-tenant（应用）
- clientget-collection-scheduler / clientget-collection-worker / clientget-scoring-worker / clientget-sending-worker（4 个后台 worker）

> **以下条目 V3 完全不实现**——不做 = 没有代码 / 没有 UI / 没有数据写入。理由列在右侧。

### 6.1 业务能力推迟

| # | 不做什么 | 理由 |
| --- | --- | --- |
| N-01 | **外贸通直采路径** | V3 仅反推（励销云 + 腾道）；外贸通直采推迟 V3.1+ |
| N-02 | **回复识别**（IMAP 自动检测 / EngageLab Inbound webhook / UI 手动标已回复）| 邮件状态 V3 不记录回复；客户回信回租户邮箱后**平台无 UI 操作入口**；推迟 V3.1+ |

| N-05 | **主联系人概念**（设主联系人 / "主联系人 vs 全部 vs 自定义" 3 选 1 目标策略）| 业务方修正"一公司多联系人都发"，目标自动按 UC-08 规则筛选 |
| N-06 | **重采机制**（关键词数据更新） | 数据冻结后不再变 |
| N-07 | **租户首登邀请邮件 + 临时密码** | 运营直接创建后线下交账号给租户 |

## 7. V3 业务侧验收

### 7.1 主链路 E2E

| # | 验收场景 | 期望结果 |
| --- | --- | --- |
| 1 | 运营 admin 端创建新租户（直接创建，无邀请邮件）+ 配域名 + 预热档位 + 配 DNS → 租户登录 → 配 OpenRouter | 租户可正常登录使用 AI 功能 |
| 2 | 租户配 1 个新关键词 → 运营启动首采 → 反推路径采集运行（励销云 → 腾道）→ 客户入库 | 客户库出现真实精准客户 + 联系人 |
| 3 | A 租户采过的关键词，B 租户配同关键词 | B 立即看到 A 当年的客户（不需重采） |
| 4 | A 客户库勾选 N 家公司 → 新建多步骤邮件计划 → 启动 → 真实发邮件 | 测试收件箱真实收到邮件 |
| 5 | A / B 两个租户都配关键词 + 操作 → 互相不可见私有状态 | 私有数据完全隔离 |
| 6 | 数据源凭证失效 → 运营更新 → 任务恢复 | 凭证维护流程通 |

### 7.2 业务侧成功标准

- ≥ 1 个真实租户的真实关键词跑通完整采集 → 邮件投递闭环
- ≥ 1 封真实邮件被真实收件人在真实邮箱收到
- 客户库有 ≥ 50 个真实采集的客户
- 邮件计划有 ≥ 5 个真实发送过的步骤
- 跨租户隔离测试通过

### 7.3 上线后观察期

- 持续观察 2 周
- 关键观察项：邮件投递成功率 / 租户使用频率 / 运营介入次数

## 8. 当前业务规模

- 5 个租户（3 archived + 2 active）
- V3 主要服务这 2 个 active 租户的真实业务运行
- 上线时间：~4-6 周后
