# 07 产品化需求规格文档（修复版 / Final for Backend Implementation）

> 本文档将 `business-flows-v2.html` 与原 `07_REQUIREMENTS_SPEC.md` 修复为可直接指导后端从 0 实现的最终需求。若与原文档冲突，以本文档为准。

## 1. 产品目标

ClientGet 是面向外贸 B2B 获客的多租户 SaaS：平台运营先配置数据源、评分模板、邮件模板、域名预热规则与 AI 模型；租户入驻后配置关键词与规则；系统持续采集潜在客户、评分、分组、发送序列邮件并追踪效果。

## 2. 用户与权限

### 2.1 平台运营

- 使用 Admin App。
- 角色：`platform_admin`。
- 管理：数据源账号、平台评分模板、情报源、平台邮件模板、域名预热规则、AI 模型、租户、租户域名、租户团队、租户 AI 余额。

### 2.2 租户用户

- 使用 Tenant App。
- 角色：
  - `admin`：租户全部权限。
  - `operator`：日常业务操作，不可管理设置类资源。
  - `viewer`：只读。
- 租户内所有用户看到同一批客户数据，不做业务员级隔离。

## 3. 全局业务决策

| 主题 | 最终口径 |
|---|---|
| 多租户隔离 | PostgreSQL RLS + `tenant_id`。 |
| 原始公司数据 | 共享池去重，租户视图隔离。 |
| 评分 | 规则为主 + LLM 辅助维度。 |
| 评级 | S/A/B/C/D。 |
| 采集通信 | 独立采集服务通过 Internal API 调主系统，不引入 MQ。 |
| AI Key | 平台级 OpenRouter 统一管理。 |
| AI 余额 | 租户人民币余额；Phase 1 平台手动充值。 |
| 邮件发送 | EngageLab；发送计划只负责发送，不负责采集/评分。 |
| 通知 | Phase 1 站内通知。 |
| 行业属性 | 租户单行业。 |

## 4. Phase 0 — 平台基础配置

### 场景 1：配置数据源渠道与账号

平台运营在 Admin 端维护三类数据源：

| source_type | 默认别名 | 用途 |
|---|---|---|
| `waimao_tong` | A01 | 关键词直接搜索海外公司。 |
| `tengdao` | B01 | 海关/采购商数据搜索。 |
| `lixiaoyun` | C01 | 中国同行搜索 → 反查出口对象 → 精准客户。 |

后端必须支持：

- 渠道开关、别名、用途描述。
- 多账号凭证池，凭证 AES-256-GCM 加密。
- 账号轮换顺序、日配额、错误计数。
- 每渠道采集频率、批量上限、执行窗口。
- 落库规则配置。

关键词不在平台侧配置，由租户管理员配置。

### 场景 2：配置行业评分模板

平台运营维护行业默认评分模板。新租户创建时复制一份快照到租户空间，之后租户可独立修改。

默认评分维度示例：

| 维度 | 类型 | 说明 |
|---|---|---|
| 工厂性质 | rule | 贸易商/制造商/两者兼具。 |
| 公司规模 | rule | 员工数/营收/成立年份。 |
| 进出口数据 | rule | 有无与频次。 |
| 联系人丰富度 | rule | 有效联系人数量。 |
| 数据来源 | rule | A01/B01/C01 权重。 |
| 产品/行业匹配度 | llm | 语义相关性，扣 AI 余额。 |

评分等级：

- S：精准客户，通常来自励销云反查或总分 >= 90。
- A：>= 80。
- B：60-79。
- C：40-59。
- D：< 40。

### 场景 3：维护行业情报源

平台运营维护行业情报源。系统每天采集、摘要、分类，然后按租户行业推送。

后端必须支持：

- RSS / website / manual 三类源。
- Excel 批量导入。
- 行业标签匹配。
- AI 摘要费用按成功预授权的订阅租户均摊。
- 余额不足租户只看到标题和原文链接，不展示 AI 摘要。

### 场景 4：配置行业邮件模板

平台运营维护官方模板，租户可使用或复制为自有模板。

模板变量统一采用双花括号：

```text
{{公司名称}} / {{联系人姓名}} / {{联系人职位}} / {{产品标签}} / {{租户公司名}}
```

后端保存时需同时维护机器变量名映射，避免中文变量直接进入服务逻辑。

### 场景 5：配置域名预热规则

最终采用动态指标驱动 6 档：

| level | default_daily_limit |
|---|---:|
| 1 | 50 |
| 2 | 100 |
| 3 | 200 |
| 4 | 500 |
| 5 | 1000 |
| 6 | 4000 |

每档配置：最低停留天数、最小送达率、最大退信率、最大投诉率。指标异常自动降档并通知平台运营。

### 场景 6：配置统一 AI 模型

平台运营维护 OpenRouter 模型与定价。

必须支持四个 scene：

- `scoring`
- `email_generation`
- `intelligence_summary`
- `data_analysis`

每个 scene 配默认模型；邮件生成可由用户在可用模型中切换。

## 5. Phase 1 — 租户入驻

### 场景 7：创建租户、配置域名、充值 AI 余额

Admin 创建租户时必须在同一事务或可恢复 workflow 中完成：

1. 创建 tenant。
2. 创建初始 admin 用户，`must_change_pwd=true`。
3. 复制平台行业评分模板为租户评分模板。
4. 复制行业官方邮件模板为租户模板或建立只读可见关系。
5. 初始化联系人规则。
6. 可选：录入发信域名与 DNS 记录。
7. 可选：充值 AI 余额并写流水。

Phase 1 不做租户自助支付。

### 场景 8：租户首次登录与配置

租户 admin 首次登录进入 onboarding：

1. 修改密码，必填。
2. 配置采集关键词，至少 1 个，必填。
3. 审阅/修改评分规则，可跳过。
4. 审阅/修改联系人规则，可跳过。
5. 完成后 `needs_onboarding=false`。

关键词必须支持 countries 与 source_types：

```json
{
  "keyword": "multilayer PCB",
  "countries": ["DE", "US"],
  "source_types": ["waimao_tong", "tengdao", "lixiaoyun"]
}
```

## 6. Phase 2 — 日常使用

### 场景 9：公司列表

公司列表是本租户可见的全量公司池，展示未评分、评分中、待补全、已评分等状态。

必须支持：

- 多维筛选：国家、行业、产品标签、规模、来源、精准标记、是否有邮箱、入库时间。
- 手动添加。
- Excel 批量导入。
- 加入黑名单。
- 公司详情 Drawer：基本信息、评分明细、联系人、邮件记录。

待补全公司可见，可加入群组，但不能进入发送计划。

### 场景 10：优选客户与群组

优选客户 = 已评分公司集合，默认展示所有等级并按 S/A/B/C/D 排序。

群组以公司为主实体：

- 群组成员引用 `tenant_company_id`。
- 可选覆盖 `tenant_contact_id`。
- 若未覆盖，发送时使用公司当前默认联系人。

### 场景 11：邮件模板

租户可查看平台官方模板 + 租户自有模板。

- viewer：只读。
- admin/operator：新建、编辑、删除自有模板；复制官方模板；AI 生成。
- AI 生成余额不足时按钮置灰，由 `GET /ai-capabilities` 控制。

### 场景 12：发送计划

创建发送计划 6 步：

1. 基本信息。
2. 收件人来源：群组 / 手动 / 筛选。
3. 首封模板。
4. 发送策略：时区、时间窗口、间隔、发信域名。
5. 序列步骤。
6. 预览确认。

启动计划前必须校验：

- 至少一个可发送收件人。
- 所有步骤模板存在。
- 首封 step 1 `condition_type=always` 且 `delay_days=0`。
- 发信域名 DNS verified。
- 域名当日额度可用。
- 收件人非黑名单、非退订、非 bounced，且公司 data_status=complete。

运行中只允许：

- pause/resume/cancel。
- append-only 追加收件人。
- 修改尚未执行的未来 step 模板和 delay。

### 场景 13：邮件监控与 AI 数据分析

邮件监控展示：

- 发送、投递、打开、点击、回复、退信、退订。
- 按计划、模板、评级、步骤、时间趋势聚合。
- AI 分析建议消耗 AI 余额。

Webhook 事件必须幂等，并在同一事务内更新 email/enrollment/contact 状态。

## 7. 后台任务

### A：数据自动采集

- 独立采集服务定期 claim tasks。
- 直接采集：外贸通 + 腾道。
- 竞对反查：励销云 → 中国同行 → 外贸通/腾道反查海外对象。
- 主系统根据 task 和 keyword 关系写入所有关联租户。

### B：情报自动采集

- 按源频率抓取。
- AI 摘要和分类。
- 发布到同行业租户。
- 费用按租户均摊。

### C：评分计算 T+1

- 对完整数据执行评分。
- 规则维度一定执行。
- LLM 维度余额不足则 pending。
- 充值后触发补评。

### D：域名额度监控

- 每日用量按域名原子 reserve。
- 指标达标升档，异常降档。
- 当日额度用完，计划暂停或等待次日继续。

## 8. 非功能性要求

| 维度 | 要求 |
|---|---|
| 安全 | JWT、RLS、CORS 白名单、凭证加密、请求限流、审计日志。 |
| 幂等 | 创建类 POST 支持 `Idempotency-Key`；Internal/Webhook 支持 `X-Request-Id`。 |
| 可观测性 | request_id、结构化日志、任务运行日志、AI usage、Webhook retry。 |
| 数据保留 | email_events metadata 90 天后脱敏；分区表按月维护。 |
| 性能 | 列表游标分页；分区表双字段 cursor。 |
| Phase 1 限制 | 不做自助支付、不做多行业租户、不做消息队列、不做移动端。 |
